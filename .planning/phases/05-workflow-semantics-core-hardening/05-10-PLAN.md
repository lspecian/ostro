  <behavior>
    - **race-fuzz** `{seed, sleeps_ms: [..], signals: [names], nest: bool}`
      - Combines N sleeps and K signal waits with nested `select!`/`join!`.
      - Losers are cancelled.
      - Output: observed completion order, op ids and per-op outcomes (Ok, Cancelled, Timeout).
    - **signals** has three modes:
      - `fifo`: waits for "x" three times and returns the payloads in order.
      - `timeout`: waits for "x" with a 200 ms timeout and returns "timeout" or the payload.
      - `before`: sleeps first, then waits. Signals sent during the sleep are buffered.
      - `long_wait`: waits for "x" with no timeout. Used by the 05-15 resume-after-timeout test.
    - **timeouts** `{mode: sleep_forever|sleep_ms(n)|busy_steps(n)}`.
    - **tokens**
      - Creates a token and publishes it with `set_status({token})`.
      - Waits with an optional timeout.
      - Returns the payload or "timeout".
    - **can-chain** `{n, max}`: continues as new with n+1 until max, then completes with n.
    - **crash-saga** `{id, steps: 3..8, fail_pattern, sleep_ms, signal_timeout_ms}`
      - Steps with deterministic retry failures.
      - A sleep, beyond hot_wait for some runs.
      - `wait_signal("go", timeout)`.
      - A gather of 2 sleeps and a signal "extra".
      - Graceful cancel handling, with cleanup in `shielded`.
      - The output is a pure function of the input and the accepted signals. Document that function in the guest header.
    - **trivial-steps** `{n}`: n steps, each returning its index. No sleeps, no signals.
    - **phase5_guests.rs** (engine testkit, inputs fed in order)
      - race-fuzz: replay equals live for 20 seeds.
      - signals: fifo/before/timeout give the expected outputs.
      - tokens: completes on TokenCompleted and times out on WaitTimedOut;
      - all scripted signal inputs are fed as D21 `SignalPayload` + `SignalMatched{op, payload_seq}` pairs, never the legacy SignalReceived.
      - can-chain: yields RunContinuedAsNew.
      - crash-saga: a fixed input gives the documented output.
      - trivial-steps n=10: gives 10 StepCompleted in one activation.
    - **sdk_cancellation.rs**: remove the `#[ignore]` on select_loser if 05-06 added one. It must now pass.
  </behavior>

**Project setup.** Create `examples/order-saga` as a standalone cargo project:
- its own `[workspace]` table;
- `crate-type = ["cdylib"]`;
- `ostro-sdk = { path = "../../sdks/rust/ostro-sdk" }`;
- explicit pins;
- Cargo.lock gitignored.

**Workflow.** `order-saga` v1. Input: `{order_id, amount, sku, qty, fail_at?: string, settle_ms?: u64, approval_timeout_ms?: u64}`. Steps:
1. `reserve_inventory`.
2. `charge_payment`, with retry policy max_attempts 3 and exponential backoff.
3. `ctx.sleep(settle_ms, default 1000)`.
4. `select!` over `wait_signal::<bool>("approve", approval_timeout, default 24h)` and `ctx.cancellation()`.
5. On approve=true: `create_shipment`, then `notify_customer`, then `complete_order`, giving `{status: "completed", …}`.

**Failure path.** On a step failure, rejection, timeout or cancellation:
- Run the compensations in reverse inside `ctx.shielded`: `refund_payment` if charged, `release_inventory` if reserved.
- Return `{status: "compensated", reason}`, or fail as Cancelled when cancellation was requested.

Steps are pure simulations; `fail_at` forces a failure.

**README quickstart.** List the exact commands:
1. `rustup target add wasm32-wasip2`
2. `cargo build --release --target wasm32-wasip2`
3. `ostro dev`
4. `ostro deploy target/wasm32-wasip2/release/order_saga.wasm --activate`
5. `ostro run order-saga --input '{…}'`
6. `ostro signal <run> approve --payload true`
7. `ostro result <run> --wait`

Note that the CLI verbs land in 05-14.
