```rust
let mut resolve = wit_parser::Resolve::default();
let (prev_pkg, _) = resolve.push_dir("tests/wit-fixtures/base")?;
let (new_pkg, _)  = resolve.push_dir("tests/wit-fixtures/add-func")?;

let new  = resolve.select_world(&[new_pkg],  Some("workflow"))?;
wit_component::semver_check(resolve, prev, new)?;
```
Caveats:
- semver_check requires both worlds to share the package name and ignores versions.
- A 2024 report says two versions of one package in one Resolve may fail to load.

Fallback: put each package in its own Resolve and run a structural diff. Every interface, type and function in prev must exist in new with an identical resolved shape, and new exports must not appear in `workflows`.

**Phase 9 pre-freeze doc comments** (09-RESEARCH § "Pre-freeze findings", PF-F3 and PF-W1..W9). Write them as in 09-RESEARCH, keeping the meaning exactly:
- **PF-W1** (journal / `resource step`): the open-step rule. Between `begin-step` returning `execute` and `complete` (or drop), every journaled call (`begin-step`, all `effects.*`, `wait`, `patched`, `set-status`) is a protocol violation that fails the activation. Context reads and `log.emit` are allowed, and randomness then comes from the step-local stream.
- **PF-W2** (`effects.wait`):
  - `any` returns **every** completed op in `ops`, at least one, ordered by completion journal seq; `all` returns all of them;
  - re-waiting an op that was already returned returns it again, and duplicates in `ops` count once;
  - `any` with an empty list is a protocol violation;
  - an unsatisfied wait appends nothing and may suspend the activation; each satisfied wait journals one `WaitResolved`, which consumes a seq.
- **PF-W3** (`types.op-id`, `effects.cancellation`): op ids are opaque u64. The cancellation op is 2^64−1, and `u64::MAX-15..` is host-reserved. JS bindings use `bigint` and must never round-trip op ids through `Number`.
- **PF-W4** (`types` header): strings are UTF-8 Unicode scalar values. StarlingMonkey replaces lone surrogates with U+FFFD and QuickJS traps. SDKs reject them first with non-retryable `invalid_string`.
- **PF-W5** (`types.payload`): `application/json` payloads are UTF-8 JSON without a BOM, and empty `data` means JSON `null`. Other content types pass through untouched.
- **PF-W6** (`retry-policy`, `step-options`, `random-bytes`):
  - `retry: none` means no host retries;
  - `max-attempts` counts the first attempt, so 0 and 1 mean no retry;
  - a NaN, infinite or < 1 coefficient is treated as 1, and delays saturate;
  - `fuel` counts guest-runtime instructions and is not portable across languages;
  - `random-bytes` takes `len` ≤ 65536.
- **PF-W7** (`effects.start-child`, `child-options`), the full child contract:
  - outcome mapping: Completed → `ok(child(output))`, Failed → `err(child failure)`, Cancelled → `err(cancelled)`, TimedOut → `err(timeout)`, Terminated → `err(non-retryable{kind: "child_terminated"})`;
  - continue-as-new chains are followed to the last run;
  - `cancel-op` on a child op completes it with `err(cancelled)` **and** requests graceful cancellation of the child and its descendants;
  - detached children have no parent linkage (`parent-run-id` none, not cancelled with the parent), and the op completes on start-accept with `child(payload{application/json, {"run_id": …}})`;
  - **PF-F3: attached children receive a graceful cancel when the parent reaches any terminal status**;
  - child run ids are deterministic from (parent run, op).
- **PF-W8** (`workflows` interface):
  - `run` is called once per activation on a fresh instance;
  - the host may end an activation by trapping inside any import (eviction, fencing, cancel), so `finally` blocks and finalizers do not run;
  - imports trap during component initialisation (pre-init/Wizer), so module-level code must not touch `context`/`effects`;
  - `describe` must be pure and return unique names.
- **PF-W9** (`context`): `uuid-v7` returns lowercase canonical 8-4-4-4-12. `random-u64` and `random-bytes` share the ctx stream; `uuid-v7` uses its own stream.
