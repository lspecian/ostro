<task type="auto" tdd="true">
  <name>Task 1: Corpus format + replay test + recorder example + server export tool</name>
  <files>crates/ostro-engine/tests/replay_corpus.rs, crates/ostro-engine/examples/record_corpus.rs, crates/ostro-engine/Cargo.toml, crates/ostro-server/examples/export_run.rs, tests/replay-corpus/README.md, Cargo.lock</files>
  <behavior>
    - `replay_corpus.rs` walks every entry directory. For each one it:
      - verifies module_sha256 and journal_sha256 and the event count;
      - prepares the module;
      - activates with the full journal and a recording sink;
      - activates with the recorded `partition`, `run_id` and `token_key_hex`. A Runtime is built with that token key, so tokens minted during replay equal the journaled ones;
      - asserts the outcome kind == expected, **the terminal payload bytes (result or failure) equal the journaled terminal event's payload** (and match `terminal_payload_sha256`), zero events appended and no NonDeterminism.

      It fails with the entry name on any mismatch, and it passes with a clear message when the directory is empty (bootstrap).
    - Negative controls in the same test file run on temp copies:
      - a flipped journal byte → sha mismatch reported;
      - a truncated journal (last event dropped) → the replay appends events or diverges, and the test detects it.
    - `record_corpus <guest> <entry-name> --input JSON [--inputs inputs.json]` runs a guest on the engine testkit, feeding scripted inputs (signals, timers, tokens) in order until the run is terminal. It then writes the entry directory with entry.toml metadata, including partition, run_id, token_key_hex (the testkit's fixed test key) and terminal_payload_sha256. It refuses to overwrite an existing entry.
    - `export_run --data-dir D --run R --entry NAME` opens a stopped data dir read-only, reads the run's journal (`journal_io::read_journal`) and module bytes (blob store by module_sha), and writes an entry. partition and run_id come from the record; the token key is read from the stopped node's meta (test/dev data dirs only; refuse to export when the key cannot be read, and document that production keys must never be committed). It refuses to overwrite.
  </behavior>
  <action>
Implement as described. README rules:
- never re-record;
- server-exported entries (export_run) contain the **ephemeral test token key** of the dev/test data dir they came from. It is not a secret and is never a production key. Never export from a production data dir;
- add new entries for new behaviours;
- every Wasmtime bump PR must keep all entries green;
- `recorded_with` is informational;
- cross-arch is covered by the default suite on the aarch64 legs; local runs cover x86_64 gnu + musl (ci-local musl leg).

If `cargo test` cannot see `tests/replay-corpus` because of the package boundary, locate it relative to `CARGO_MANIFEST_DIR`.
  </action>
  <verify>
    <automated>cargo test -p ostro-engine --test replay_corpus --locked && cargo build -p ostro-engine --example record_corpus --locked && cargo build -p ostro-server --example export_run --locked</automated>
  </verify>
  <done>The tooling works, the negative controls prove the test catches corruption and divergence, and both tools refuse to overwrite.</done>
</task>
