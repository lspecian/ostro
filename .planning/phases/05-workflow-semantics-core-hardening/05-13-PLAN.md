  <name>Task 1: ostro-cli client + output layer + run/ls/inspect/history/deploy verbs</name>
  <files>Cargo.toml, Cargo.lock, crates/ostro-cli/Cargo.toml, crates/ostro-cli/src/lib.rs, crates/ostro-cli/src/client.rs, crates/ostro-cli/src/output.rs, crates/ostro-cli/src/commands/mod.rs, crates/ostro-cli/src/commands/runs.rs, crates/ostro-cli/src/commands/deploy.rs</files>
  <behavior>
    - Global flags: `--server` (env OSTRO_SERVER, default http://127.0.0.1:7700), `--json`, `--timeout` (default 30 s).
    - `Client`:
      - holds typed methods returning `serde_json::Value` bodies, so `--json` prints the body verbatim (pretty-printed);
      - `ApiError` bodies are preserved;
      - connection errors produce a clear message and exit 1.
    - `run <workflow> [--input JSON|@file] [--version N] [--queue Q] [--idempotency-key K] [--conflict reject|return] [--delay DUR] [--tag k=v]… [--schedule-to-start DUR] [--retention DUR] [--wait[=DUR]] [--dry-run]`:
      - `--wait` long-polls the result after the start;
      - `--dry-run` sends `dry_run=true` on the start request (server-side validation, added in 05-12) and prints the would-be outcome (new run, or existing run id under `--conflict return`).
      - Duration flags use the same friendly format as the server (`30s`, `168h`). Days are written as hours, because jiff rejects `7d`. A unit test asserts that `7d` gives a clear usage error suggesting `168h`.
    - `ls [--workflow --status --queue --tag --limit --page]`, `inspect <run>`, `history <run> [--limit]`.
    - `deploy <file.wasm> [--activate]`:
      - compute the sha256 and PUT the module (201 created, 200 unchanged);
      - with `--activate`, read the module's described workflows from the upload response or `GET /v1/workflows`, and activate each described version.
    - Human output is short tables/lines. Unit tests cover argument parsing (clap `try_parse_from`), `@file` input loading and the duration parsing.
  </behavior>
  <action>
Build the crate as a library: `pub fn command() -> clap::Command` (or derive structs) and `pub async fn dispatch(args) -> ExitCode`, so `crates/ostro` can embed it. Use the same clap version and style as 04-19. Add reqwest as described and check `cargo deny check` and `cargo tree -d` for duplicates.
  </action>
