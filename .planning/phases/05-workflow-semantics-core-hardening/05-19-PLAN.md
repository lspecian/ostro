<objective>
Build the QA-01 whole-server crash campaign on top of 05-18's failpoint binary. It has five parts:
1. a workflow load generator with an ack log;
2. a checker for "no lost accepted runs and no duplicate journal entries", proven by negative controls;
3. a sharded, resumable runner whose every counted fault ends in `kill -9`;
4. a CI smoke run;
5. a measured projection of how long the ≥ 10,000-kill gate (05-20) will take.

Why sharded: reopen time grows with segment count (02-15), so 10k sequential kills on a single data dir would be far too slow.

Purpose: success criterion 3 and the docs/05 "10,000 random kill -9 during load" exit item.

Output: the crashtest modules, two suites and the smoke step.
</objective>

  <name>Task 1: Server target + workload generator + checker (journal invariants) with negative controls</name>
  <files>crates/ostro-crashtest/Cargo.toml, crates/ostro-crashtest/src/lib.rs, crates/ostro-crashtest/src/server_target.rs, crates/ostro-crashtest/src/workload.rs, crates/ostro-crashtest/src/check.rs, crates/ostro-crashtest/tests/check_controls.rs, Cargo.lock</files>
  <behavior>
    - **ServerTarget**
      - Builds the failpoint binary once per process (`cargo build --release -p ostro --features failpoints --target-dir target/failpoints`), or locates an existing one.
      - Spawns `ostro dev --data-dir <dir> --listen 127.0.0.1:<port>` with `FAILPOINTS` set.
      - Waits for readiness, uploads crash-saga and activates it.
      - Offers `kill9()` and `restart()`.
    - **Workload** (reqwest)
      - N concurrent starters with idempotency keys, 10% of them deliberate duplicates.
      - Sends signals "go" and "extra" with request_id, including retries.
      - Cancels 5% of runs and terminates 2%.
      - Records every 2xx in an AckLog: an append-only file, fsync per record.
    - **check**
      - (a) every acked run exists after restart;
      - (b) after the final settle every acked run is terminal; Completed runs have result == `crash_saga_expected(input, accepted signals)`; cancelled and terminated runs carry the correct status (a cancel acked after completion is a no-op);
      - (c) every journal invariant listed in the must-haves holds;
      - (d) `rebuild_and_compare` on a copy every K iterations;
      - (e) acks received just before a kill are not lost.
    - **check_controls.rs** (default suite, no server): synthetic histories and ack logs for each failure class below. Each one must produce its own specific error:
      - lost ack;
      - duplicate StepCompleted;
      - two completions for one op;
      - duplicate request_id signal;
      - wrong result.
  </behavior>

<task type="auto" tdd="true">
  <name>Task 2: Sharded resumable kill campaign + report + CI smoke + timing projection</name>
  <files>crates/ostro-crashtest/src/campaign.rs, crates/ostro-crashtest/src/lib.rs, crates/ostro-crashtest/tests/server_campaign.rs, scripts/ci-local.sh, .github/workflows/ci.yml</files>
  <behavior>
    - **Environment variables**
      - `OSTRO_CAMPAIGN_FAULTS`: total kills (default 20).
      - `OSTRO_CAMPAIGN_SHARDS`: default 1; the gate uses 20.
      - `OSTRO_CAMPAIGN_SHARD_IDS`: subset such as `0-4`.
      - `OSTRO_CAMPAIGN_PARALLEL`: default min(6, cores/2).
      - `OSTRO_CAMPAIGN_STATE_DIR`: required for runs launched by the gate and timing steps; default `target/campaign`. Each run type uses its own directory and never shares one: smoke uses `target/campaign-smoke`, which is wiped before every smoke; timing uses `target/campaign-timing`, wiped before the timing run; the gate uses `target/campaign-gate`, which 05-20 starts clean.
      - `OSTRO_CAMPAIGN_SEED`.
    - **One iteration = one counted fault, and it always ends in `kill -9`.** The variant is chosen per iteration:
      - (i) plain: kill -9 at a uniformly random time under load;
      - (ii) failpoint: arm a random site with `1%return`, or `enospc` where supported, then kill -9 after the server logs a partition failure or after T;
      - (iii) ENOSPC: an ENOSPC variant on a WAL, blob or meta write site, then kill -9.
    - **Counting**
      - `kills` is incremented only after the kill is confirmed (waitpid shows SIGKILL).
      - Injected errors observed before the kill are counted separately, as `failpoint_hits`, for information.
    - **Per shard**
      - Fresh data dir and port; quota = `FAULTS / SHARDS`.
      - Persists `shard-NN.json` = `{kills, by_variant{plain, failpoint, enospc}, failpoint_hits, last_seed, failures[]}` after every iteration, and resumes from it. Each shard file also records its run identity: `shards`, `faults`, `seed`. The runner **refuses to resume** a shard file whose recorded SHARDS, FAULTS or seed differ from the current run. It exits non-zero with a message telling the user to wipe the state dir, and a unit test covers this.
      - Runs checks (a)+(c) after each restart, (d) every 25 iterations and (b) at shard end.
    - **Report**: a test named `report`, run with `-- --ignored report`, aggregates every shard file. It prints `kills=<n> lost_acked_runs=<n> duplicate_journal_entries=<n> non_terminal_runs=<n>` and a table. It exits non-zero on any violation or when kills is below `OSTRO_CAMPAIGN_FAULTS`.
    - **Smoke**: always uses a fresh dir. Run `rm -rf target/campaign-smoke` first, then `OSTRO_CAMPAIGN_STATE_DIR=target/campaign-smoke OSTRO_CAMPAIGN_FAULTS=20 cargo test --release -p ostro-crashtest --features failpoints --test server_campaign -- --ignored --nocapture campaign`, followed by `report` with the same env. Add it to ci-local.sh after the failpoint suites, including the `rm -rf target/campaign-smoke` wipe, and mirror it in ci.yml with the same wipe.
    - **Timing projection**
      - Wipe `target/campaign-timing`, then run 200 kills as 4 shards with parallel 4, using `OSTRO_CAMPAIGN_STATE_DIR=target/campaign-timing`.
      - Record seconds per kill.
      - Project the wall time of the gate (20 × 500, parallel 6).
      - Put the projection in the SUMMARY and in a comment in campaign.rs.
  </behavior>
