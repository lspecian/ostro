  <behavior>
    - **Await tokens.** `ctx.create_await_token(timeout: Option<Duration>) -> AwaitToken<T>` with `.token() -> &str` and `.op() -> Op<T>`. The completion payload is decoded as JSON.
    - **Continue-as-new.**
      - The workflow returns a continuation through the most ergonomic shape that fits the existing `Workflow` trait and the `__run` mapping, for example `Err(WorkflowError::continue_as_new(input))` or a `ContinueAsNew` return. Document the choice.
      - It maps to `run-result::continued-as-new` and may carry an optional workflow/version.
    - **D11 cancellation.**
      - `Op::wait()` waits on `[op, CANCELLATION]` with `Any` and returns `Err(StepError::cancelled())` if cancellation completes first.
      - `join!` and `select!` include the cancellation op the same way.
      - A wait on `ctx.cancellation()` itself is not double-wrapped.
      - Inside `ctx.shielded(|| …)`, waits use the plain op list. Implement this with a thread-local depth counter.
    - **README** documents:
      - patched memo and unqueried-marker skip (D6);
      - step-local RNG (D7);
      - FIFO signals;
      - signal and token waits always evicting, never hot-parked;
      - cancellation surfacing and `shielded` cleanup;
      - await-token one-shot semantics;
      - continue-as-new;
      - the Phase 9 portability conventions, mirrored from the WIT: open-step rule (PF-W1), JSON payload/empty = null (PF-W5), `uuid_v7` own stream vs `random_*` shared stream (PF-W9);
      - `ctx.info().attempt` (Phase 7 F4): it changes on every re-dispatch and is not replay-stable. Use it for logging and metrics only, never for control flow.
  </behavior>
