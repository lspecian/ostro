<task type="auto" tdd="true">
  <name>Task 1: Waits registry, signals (SignalRun + inbound Signal), wait timeouts, CancelWait</name>
  <files>crates/ostro-partition/src/apply/waits.rs, crates/ostro-partition/tests/apply_waits.rs</files>
  <behavior>
    - RegisterWait{op, Signal(name), timeout_due_ms}:
      - inserts both wait key shapes, plus timer `(due, run, op)` when due > 0;
      - if the inbox has a signal for `name` (one prefix read), journals SignalReceived{op, payload} immediately, deletes that inbox row and the just-written wait and timer rows, and emits InputAppended. The run is Running, because the intent came from its own executor.
    - RegisterWait{op, Token, due}: inserts the wait row and timer only. Tokens are never buffered.
    - SignalRun:
      - unknown run → RunNotFound; terminal → RunTerminal;
      - request_id present and in SignalSeen → Duplicate; otherwise insert SignalSeen;
      - oldest wait for name present → journal SignalReceived for it, remove its rows and timer, and wake (Scheduled → Ready + EnqueueReady; Running → InputAppended; Ready → nothing);
      - no wait → push to the inbox at `(run, name, inbox_next)`.
    - Inbound outbox Signal follows the same logic as SignalRun, except for dedupe: cross-partition dedupe is the existing `(src, seq)` dedupe.
    - try_wait_timeout(run, op): wait row present → journal WaitTimedOut{op}, remove both wait shapes, delete the timer row, wake, return Some(Accepted). Absent wait row → None (ordinary timer path).
    - CancelWait{op}: removes the wait rows and timer. Absent → no-op inside EventsAppended; the intent never rejects the batch.
    - FIFO tests:
      - two waits on "x" and one signal → the lower op completes;
      - three signals before any wait → consumed in send order by successive RegisterWaits;
      - signal-after-timeout → inbox;
      - timeout-after-signal → no-op, exactly one completion event for the op.
    - Read-count tests for SignalRun and RegisterWait.
  </behavior>
  <action>
Fill the waits.rs stubs from 05-02. Remove a timer row by key: the due time is in the WaitRow. Keep the 05-02 behaviour of `inbound_signal` as the "no wait" branch.

Test through `apply_command` with in-memory store helpers from `tests/common`. Use only the existing helpers; add new helpers in apply_waits.rs itself, because tests/common/mod.rs belongs to 05-02 and other plans.
  </action>
  <verify>

  </verify>
  <done>Signals, the waits registry and wait timeouts follow the FIFO and once-only semantics.</done>

  <behavior>
    - CompleteToken{run, op, payload}:
      - token wait row present → journal TokenCompleted, remove rows and timer, wake → Accepted;

      - terminal run → RunTerminal; unknown run → RunNotFound;

    - RequestCancel{run, reason}:
      - non-terminal and not yet cancel_requested → set the flag and `cancel_reason`, journal CancelRequested{reason}, wake, and cascade a graceful CancelRun to the children through the outbox (existing cascade helper);

    - Inbound CancelRun takes the same path; its outcome per message follows the InboundBatch rules.

Document this case and test that no event is written at seq 0 by apply.
