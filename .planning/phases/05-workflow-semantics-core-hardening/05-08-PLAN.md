Workflow `order-saga` v1, input `{order_id, amount, sku, qty, fail_at?: string, settle_ms?: u64, approval_timeout_ms?: u64}`:
1. `reserve_inventory`;
2. `charge_payment`, with retry policy max_attempts 3 and exponential backoff;
3. `ctx.sleep(settle_ms, default 1000)`;
4. `select!` over `wait_signal::<bool>("approve", approval_timeout, default 24h)` and `ctx.cancellation()`;
5. on approve=true: `create_shipment`, `notify_customer`, `complete_order` → `{status: "completed", …}`.

On a step failure, rejection, timeout or cancellation, run the compensations in reverse inside `ctx.shielded`: `refund_payment` if charged, `release_inventory` if reserved. The result is `{status: "compensated", reason}`, or the run fails as Cancelled when cancellation was requested. Steps are pure simulations (effects arrive in Phase 6); `fail_at` forces a failure for tests.

README quickstart, with the exact commands:
1. `rustup target add wasm32-wasip2`
2. `cargo build --release --target wasm32-wasip2`
3. `ostro dev`
4. `ostro deploy target/wasm32-wasip2/release/order_saga.wasm --activate`
5. `ostro run order-saga --input '{…}'`
6. `ostro signal <run> approve --payload true`
7. `ostro result <run> --wait`
