  <behavior>
    - **`names.rs`:**
      - `validate_tenant(&str)`: grammar `^[a-z0-9][a-z0-9-]{0,62}$`; `_` is rejected as reserved.
      - `validate_name(&str)`: grammar `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`, so no `/`, `:` or leading `__`.
      - `qualify(tenant: Option<&str>, name) -> String`: `"<tenant>/<name>"`, or the bare name for the default tenant.
      - `split_qualified(&str) -> (Option<&str>, &str)`: a key is qualified iff the prefix up to its first `/` matches the tenant grammar.
      - Unit tests cover the boundary cases.
    - **Start path (`control/runs.rs`):**
      - validate the tenant and the workflow and queue names;
      - set `StartRun.workflow` and `queue` to the qualified forms before computing dedupe and routing;
      - enforce `tenant(StartRun.workflow) == StartRun.tenant`;
      - signal names are validated with the same grammar (signal APIs land in 05-13, which reuses `validate_name`).
    - **`tenancy_api.rs`:**
      - invalid names (`a/b`, `x:y`, `__z`) and the tenant `_` → 400 over REST and gRPC;
      - default-tenant starts are unchanged.
  </behavior>
  <action>Implement the helpers and wire them into the start path with minimal diffs.</action>
