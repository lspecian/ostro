  <behavior>
    - Dry run over tag `t` with 30 matching runs → `matched_estimate == 30`, 20 samples, no job created, nothing changed.
    - Bulk cancel of 30 sleeping runs → all cancelled; `done == 30`; a second job over the same filter → all `skipped`.
    - **Snapshot bound:** 50 Failed runs tagged `t`; bulk rerun `from_step s3` on v2 → exactly 50 new runs (each `__bulk/<job>/<run>` dedupe, copying tag `t`), job ends `done`, no rerun of a rerun.
    - **Pacing** (paused tokio time / FakeClock): rate 10/s, burst 2, 40 ops → after the burst, op start times are ≥ 100 ms apart; total elapsed ≥ 3.8 s logical.
    - **Backpressure:** with `backlog_high = 5` and a paused queue holding 10 ready runs on the target partition, a bulk retry pauses (state `paused_backpressure`) and resumes when the backlog drains.
    - **429:** a bulk restart on a queue with a Phase 7 rate limit sees 429 and waits `retry_after_ms` before retrying the same run (no failure counted).
    - Signal bulk uses `request_id = <job>/<run>` (64-byte cap respected: sha-shortened when needed); re-running the job sends no duplicate (the signal_seen dedupe answers duplicate → counted as done).
    - Requeue bulk on DLQ members writes Requeued marks; pause/resume bulk calls the Phase 7 methods.
    - Limits: a 5th concurrent job → 429-style `bulk_too_many_jobs` (code per 11-09 SUMMARY); a filter matching more than `max_matches` (test config 100) → 400 `bulk_too_many_matches`.
    - `GET /v1/bulk/{id}` reports matched/done/skipped/failed (≤ 100 reasons) and eta; `POST /v1/bulk/{id}/cancel` stops the job within one op; `GET /v1/bulk` lists jobs.
