Index eligibility: `!req.tags.is_empty() || req.order == Newest || req.dlq`. Prefix choice: first tag → Tag; else workflow → Workflow; else `dlq` → Status(Failed) ∪ Status(TimedOut) (two prefixes merged); else terminal status → Status; else → All (`0x05`, every run newest first). Remaining filters (other tags, queue, non-terminal status, created_*) apply in memory on the decoded RunRecord within the scan budget. Non-terminal status filters (Ready/Running/Suspended) with `order=newest` use the All prefix plus the in-memory filter. DLQ membership (marks): call `p11_dlq::is_dlq_member(ctx, &run, &rec)`, a 11-02 stub (returns true for Failed/TimedOut) that 11-10 implements in the same wave in its own file; 11-09's test for `dlq=true` therefore asserts only the status selection, and 11-10's `dlq_api` asserts the marks.
While the index is rebuilding, `order=newest` without an index cannot be served newest first (there is no reverse scan): the fallback returns the budgeted scan in oldest order with the response header `X-Ostro-Order-Fallback: oldest` (documented in docs/operations.md by 11-16).
