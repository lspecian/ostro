    pub enum CommandResult<'a> { Replayed(&'a Event), Live { seq: u64, ts_nanos: u64 } }

    Semantics and cases (write tests first in replay/tests.rs, `#[cfg(test)] mod tests;`):
    - cursor_live_appends: empty journal (only RunStarted) → `command()` returns Live with seq 1, 2, 3...; each live event gets `ts_nanos = clock.now_unix_nanos()` at creation and is pushed to pending; op ids are seqs.
    - cursor_replay_no_appends: record a sequence live, build a new ReplayState from RunStarted + recorded events, issue the same commands → every call returns Replayed(event with that seq), pending stays empty, is_replaying true until the last command then false.
    - cursor_skips_inputs: input events (TimerFired, EffectCompleted, SignalReceived, ...) interleaved between guest commands are skipped by next_guest_command and never compared.
    - cursor_divergence_changed_hash / changed_kind: mismatch → `ReplayError::NonDeterminism { seq: <journal seq of expected event>, expected: <event.summary() + hash hex>, actual: <actual() + hash hex> }`.
    - finish_trailing_commands: after replaying k of n recorded commands, `finish()` → NonDeterminism at seq of the (k+1)th command with actual "run returned"; a trailing terminal event (RunCompleted/RunFailed/RunContinuedAsNew) is NOT considered trailing when the guest is about to emit its own terminal command (terminal comparison happens through `command(Terminal, ..)`).
    - proptest replay_property (cases from PROPTEST_CASES, default 256): arbitrary sequences of 1..40 commands (kinds from CommandKind, random hashes) with random input events interleaved; recording then replaying the identical sequence → zero pending; applying exactly one mutation (swap two adjacent commands with different (kind,hash); insert an extra command; delete one; change one hash) → the first error is NonDeterminism and its `seq` equals the journal seq of the first differing recorded command (for delete-at-end/extra-at-end: finish() or the first live-vs-recorded mismatch — specify each in the test).
    - time_rule: logical now = accepted_at before any command; after replaying command with ts T it is T; input events with larger ts do not change it; live command creation sets it to the new event's ts; identical values at identical program points across record and replay.
    - wait_live_resolution: ops [a, b] with EffectCompleted(b) at seq 7 and TimerFired(a) at seq 9 → mode Any → Resolved([b, a]) (journal order, all completed ops returned), mode All with only b completed → Pending (no event appended); Resolved appends WaitResolved{completed} with the given hash.
    - wait_replay: next guest command must be WaitResolved with equal hash → returns its recorded list even if more completions exist now; hash mismatch → NonDeterminism.
    - wait_cancellation_op: ops [CANCELLATION_OP, t]; CancelRequested input present → Resolved includes CANCELLATION_OP in journal order of the CancelRequested event; completion_for(CANCELLATION_OP) returns that event.
    - deliver_inputs: appends committed inputs with contiguous seqs; rejected (BadJournal) if pending is non-empty or seq gap.
    - patched_semantics: live → true + PatchMarker appended; replay with matching marker next → true, consumed; replay where next guest command is something else → false, nothing consumed, no error.
    - step_guard: live `begin_step` reserves seq N (pending unchanged); any `command()`/`wait()`/`patched()` before `complete_step(N, ..)` → ReplayError::Protocol("journaled command inside an open step"); `complete_step` appends exactly one StepCompleted at seq N; replay `begin_step` with a matching StepCompleted next returns Replayed and opens no guard; `abandon_step` lets the next command reuse seq N.
    - continue_as_new_suggested: true iff (seq of last consumed/appended guest command + 1) >= threshold; identical at identical program points in record and replay (prove with a test that queries mid-sequence in both modes).
    - golden_rng_streams (rng.rs): `ChaChaStream` = chacha20 (RFC 8439 ChaCha20, `chacha20::ChaCha20`) with key = seed bytes, nonce = (stream as u32).to_le_bytes() ‖ [0u8; 8], output = keystream bytes consumed sequentially (`apply_keystream` over zeroed buffers, keeping position). Fixed seed [7u8;32] → first 32 bytes of each of the four streams equal committed hex constants in the test; streams differ from each other; `next_u64()` = 8 bytes LE; `fill(buf)`. `insecure_seed(seed)` = first 16 bytes of sha256(b"ostro/insecure-seed/v1" ‖ seed) as two LE u64 (golden). `uuid_v7(now_ms, stream)` = 48-bit ms ‖ version 7 ‖ 12+62 random bits from the Uuid stream with RFC 9562 variant bits, lowercase hyphenated (golden for fixed inputs; version/variant nibbles asserted).
    - await_token (token.rs): `mint(partition: u16, run_id: &str, op: u64, key: &[u8; 32]) -> String` = `"ot1_" + base32_lower_nopad(partition BE ‖ len(run_id) as u8 ‖ run_id bytes ‖ op BE ‖ hmac_sha256(key, those bytes)[..10])`; `parse(&str) -> Option<TokenParts { partition, run_id, op }>`; `verify(&str, key) -> bool` (constant-time via `hmac::Mac::verify_truncated_left` or `verify_slice` on the 10-byte prefix). Tests: round trip, wrong key → false, flipped char → parse None or verify false, golden token for fixed inputs. Hand-roll RFC 4648 base32 (lowercase alphabet, no padding) in ~25 lines with its own test vectors ("foobar" → "mzxw6ytboi").
