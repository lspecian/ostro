  <name>Task 1: Hot-wait, ParkedRegistry LRU budget eviction, and live input delivery in the testkit</name>
  <files>crates/ostro-engine/src/host/effects.rs, crates/ostro-engine/src/host/state.rs, crates/ostro-engine/src/limits.rs, crates/ostro-engine/src/activation.rs, crates/ostro-engine/src/testkit.rs, crates/ostro-engine/tests/hot_wait.rs</files>
  <action>
1. `limits.rs`: `pub struct ParkedRegistry { inner: Mutex<ParkedInner { tick: u64, parked: HashMap<u64 /*id*/, (u64 /*parked_at tick*/, CancellationToken)> }>, budget: Arc<NodeMemoryBudget> }` with `new(budget) -> Arc<Self>` that spawns one tokio task: loop { `budget.pressure().notified().await`; while `budget.is_over()` and a parked entry exists → cancel the entry with the smallest parked_at tick (least recently parked), remove it, `metrics::counter!("ostro_activation_budget_evictions_total")` }; `park(&self) -> ParkGuard` (registers a fresh token; `ParkGuard::token()`, Drop unregisters); `parked_count()`. Running (non-parked) activations are never in the registry, so budget pressure can never interrupt them (Research Pattern 9). Also make `NodeMemoryBudget::charge` notify `pressure` whenever `is_over()` after charging (if 03-03 did not already).
2. `host/state.rs`: extend `HostInit`/`HostState` with `inputs: Option<UnboundedReceiver<Event>>`, `cancel: CancellationToken`, `parked: Option<Arc<ParkedRegistry>>`, `hot_wait: Duration`; update `activation.rs` to pass them from `Activate` and the Runtime (Runtime owns one `Arc<ParkedRegistry>` built over `engine.budget()`).
3. `host/effects.rs` `wait`: on `WaitOutcome::Pending`: decide hot-waitability — every awaited op except CANCELLATION_OP must be either a TimerStarted with `fire_at_nanos − logical_now ≤ hot_wait` or an EffectScheduled (in flight), there must be an `inputs` receiver, and `!budget.is_over()`. Not hot-waitable → `Err(Evict{WaitUnsatisfied})` (unchanged). Hot-waitable → `self.flush().await` (intents MUST be committed before parking so apply can schedule timers/effects; a flush error maps to Fenced/AppendConflict as in 03-08 — return a typed error the driver understands), `let guard = parked.park()`, then loop with a single deadline `Instant::now() + hot_wait`: `tokio::select! { Some(ev) = inputs.recv() => { replay.deliver_inputs(vec![ev, ..drain try_recv]) ; re-run replay.wait(...) — Resolved → build completions and return; Pending → keep waiting }, _ = sleep_until(deadline) => Err(Evict{HotWaitElapsed}), _ = guard.token().cancelled() => Err(Evict{BudgetPressure}), _ = self.cancel.cancelled() => Err(Evict{External}) }`. Keep the import thin: only channel receives and the flush await happen here (Pitfall 1). The guest's view is unchanged: the same `wait` returns the same completions as after an evict-and-replay.
4. `testkit.rs`: add live delivery. `Script::live(delay: Duration)` makes `drive_to_completion` create an unbounded channel per activation, pass the receiver in `Activate.inputs`, and register the sender in FakeSink; when FakeSink.append receives TimerStarted/EffectScheduled events, it schedules (tokio::spawn + sleep(delay)) the scripted completion: lock state, assign seq = journal.len(), push to the journal, send the event to the activation's sender (if still open), else leave it for the next activation's journal. Inputs are only produced after the append that created the op, so seqs stay contiguous with the activation's flushed pending (the activation flushed before parking).
5. `tests/hot_wait.rs` (det-basic sleeps 5 s of logical time, so it is hot-waitable only when hot_wait ≥ 5 s: use hot_wait = 10 s for the "hot" cases, 1 s for the "cold" case, 300 ms only where a test needs a short real-time park with live delivery off):
   - `hot_wait_short_timer_one_activation`: hot_wait 10 s, `Script::live(50 ms)` → det-basic Completed with `activations == 1`.
   - `hot_wait_long_sleep_evicts_immediately`: hot_wait 1 s (det-basic sleeps 5 s logical) → first activation `Evicted{WaitUnsatisfied}` returned in < 200 ms wall; run completes after re-dispatch.
   - `hot_wait_elapsed_evicts`: hot_wait 300 ms, live delivery disabled → first activation `Evicted{HotWaitElapsed}` after ≈300 ms (assert 250 ms..2 s); completes after re-dispatch with default timer firing.
   - `hot_wait_journal_equivalence`: journals from the hot run and the evict run are equal when compared as `(seq, kind, meta.hash, recorded bytes)` ignoring `ts_nanos` (FakeClock call counts may differ); outputs equal.
   - `hot_wait_budget_lru`: Runtime with `node_memory_budget` just above one det-basic instance's charged memory; start 3 runs that park (hot_wait 10 s, live delivery off) one after another (await `parked_count()` increments), then start a 4th run that pushes the budget over → the FIRST parked run is evicted with `Evicted{BudgetPressure}` before the others; the 4th (running) run is never evicted for budget.
   - `hot_wait_external_cancel`: cancel a parked activation's `Activate.cancel` → `Evicted{External}`.
   - `bounded_budget_many_runs`: 50 concurrent det-basic runs (distinct seeds) with `node_memory_budget` = 10 × one instance → all 50 Completed with outputs equal to solo runs of the same seeds; `budget.used()` returns to 0 at the end.
