1. `guests/sandbox` (cdylib, wit-bindgen, world workflow), workflows:
   - `loop`: completes step "before", then `loop { core::hint::black_box(()) }` (no imports inside).
   - `bomb`: allocates and touches 1 MiB `Vec<u8>` chunks forever, keeping them alive.
   - `deep`: unbounded recursion with a non-trivial frame (`black_box([0u8; 256])`), no imports.
   - `deep-call`: input = `depth: u32 LE ‖ selector: u8`; recurses exactly `depth` frames (same frame as `deep`, using `black_box` so it is not optimised away), then at the bottom calls host imports with maximum-size arguments per selector: 0 none; 1 `begin-step` with a 64 KiB name then `complete(Ok(1 MiB payload))`; 2 `random-bytes(65536)`; 3 `set-status` 64 KiB JSON string; 4 `log.emit` with a 512 KiB message and 64 fields; 5 `http-fetch` with a 1 MiB body and 256 headers; 6 `wait` on 4096 op ids (sleep ops created first) — expected to evict; 7 `uuid-v7` + `now` + `info`; 8 WASI: `println!` of 64 KiB + `SystemTime::now` + `HashMap` insert; 255 = all of the above in sequence. Returns `completed` on success.
   - `step-fuel`: step "ok" (completes), then step "hot" begun with `step-options { fuel: Some(1_000_000) }` whose body loops forever.
2. `tests/sandbox.rs` (`mod common;`, multi-thread tokio):
   - `sandbox_loop_fuel`: `activation_fuel = 100_000_000` → `AttemptFailed(FuelExhausted)`; journal contains StepCompleted("before") (flushed on attempt failure).
   - `sandbox_loop_epoch`: `activation_fuel = u64::MAX / 2`, `activation_timeout = 200 ms` → `AttemptFailed(Timeout)` and the call returns in < 2 s wall.
   - `sandbox_memory_bomb`: `pool.max_memory_bytes = 64 MiB` → `AttemptFailed(MemoryExceeded)`; `engine().budget().used()` returns to baseline afterwards.
   - `sandbox_deep_recursion`: → `AttemptFailed(StackOverflow)`.
   - `sandbox_step_fuel`: → `AttemptFailed(FuelExhausted)` and the journal holds StepCompleted("ok") but not "hot"; the activation-level fuel was NOT exhausted (assert via a Runtime with a huge activation budget so only the step cap can trip).
   - `sandbox_isolation`: on ONE Runtime run concurrently (tokio::join!/spawn): loop (fuel), loop (epoch), bomb, deep, and det-basic; det-basic → `Completed` with output identical to a solo run on a fresh Runtime; the four hostile runs fail with their expected codes; afterwards a second det-basic run on the same Runtime also completes (engine still healthy).

  <name>Task 2: ENG-06 max-depth host-call test with a subprocess negative control</name>
  <files>crates/ostro-engine/tests/stack_depth.rs</files>
  <action>
`tests/stack_depth.rs` (`mod common;`):
- Helper `run_deep(rt, prepared, depth, selector) -> ActivationOutcome` via drive_to_completion (Script with fire_timers so selector 6 can finish or evict; treat `Evicted` as a non-overflow result).
- Helper `max_depth(rt, prepared, selector) -> u32`: exponential probe from 1,000 doubling until `StackOverflow`, then binary search to the largest depth that does NOT return `AttemptFailed(StackOverflow)`. Each probe is a fresh activation (Store dropped between probes).
- `stack_depth_every_import_at_max_depth`: default `EngineConfig` (async_stack_size 4 MiB, max_wasm_stack 512 KiB). For each selector in [0,1,2,3,4,5,6,7,8,255]: d = max_depth(selector); run at d, d−1 and d+1; every outcome must be one of {Completed, Evicted, AttemptFailed(StackOverflow)} — reaching the assertion at all proves the process survived (an abort would kill the test binary; under nextest that is reported as a crash; under `cargo test` the whole binary fails loudly). Print the depth per selector and the depth of selector 0 for the SUMMARY.
- `stack_depth_negative_control` (proves the test can detect the hazard): if env `OSTRO_STACK_CHILD` is unset, re-exec `std::env::current_exe()` with args `["--exact", "stack_depth_child", "--ignored", "--nocapture", "--test-threads=1"]` and env `OSTRO_STACK_CHILD=1`; the `#[ignore] stack_depth_child` test builds a Runtime with `async_stack_size = max_wasm_stack + 16 KiB` (the smallest value Wasmtime accepts above max_wasm_stack; if it rejects it, use the smallest accepted value and print it), finds max depth for selector 0, then runs selector 255 at that depth. Parent assertion: on unix, the child either exits via signal (`ExitStatusExt::signal() == Some(SIGABRT=6)` or SIGSEGV) — demonstrating the abort mode with too little host headroom — or, if it survives, the parent prints `NEGATIVE CONTROL DID NOT ABORT (headroom=..)` and fails ONLY when env `OSTRO_STACK_STRICT=1` (otherwise passes with a warning and the executor records the measured behaviour in the SUMMARY). Gate the whole negative control with `#[cfg(unix)]`.
- Document at the top of the file: why 4 MiB, the Research measurement (1.4 MiB host survived / 1.7 MiB aborted at 2 MiB / 512 KiB), and that host imports must stay thin (no heavy work in `poll`).
