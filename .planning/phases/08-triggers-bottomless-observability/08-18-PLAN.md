<task type="auto" tdd="true">
  <name>Task 2: Restore pipeline with two-step verified replay + tar archive (online/offline backup)</name>
  <files>crates/ostro-backup/src/{restore,archive}.rs, crates/ostro-backup/tests/restore.rs, crates/ostro-server/src/control/admin.rs</files>
  <behavior>
    - `restore(source: RestoreSource /*Url|Tar*/, opts {data_dir, at: Option<At>, takeover, parallelism}) -> RestoreReport`:
      1. refuse a non-empty data_dir;
      2. load the manifest (current or `--at` gen/time by walking `manifest/gen/`), verifying its sha and format;
      3. write node.toml (format_version 1, partitions = P, **new incarnation**, the `restored_from` key additive);
      4. meta bootstrap from `meta_snapshot_key` (sha verified);
      5. blobs: download all remote `blobs/` (simple and correct), verifying the sha of each;
      6. `Manifest::validate()` (08-13) first: every partition satisfies `snapshot_offset ≤ verify_offset ≤ cut_offset` and the chain-start rule; otherwise `RestoreError::BadManifest` (B3). Then per partition, in parallel: download and verify the snapshot sha → `install_snapshot` (skip when the chain starts at 0 with no snapshot); list `p/<pppp>/seg/` from `chain_start`; download; `verify_chain` (start = chain_start, last chunk sha == manifest);
      7. **two-step verified replay, in-files route (B6)**: no HW-capped open is needed.
         - (a) `write_partition_log(.., upto = verify_offset_p, Create)` with the envelopes `[S, verify_offset_p)`;
         - (b) open the Node in normal **Inspect** mode (stop after catch-up, no append, barrier closed): it replays exactly to `verify_offset_p`; compare `state_hash` to the manifest (mismatch → `RestoreError::HashMismatch{partition}`); close;
         - (c) `write_partition_log(.., upto = cut_p, Append)` with `[verify_offset_p, cut_p)`;
         - (d) Inspect again → the state at the cut.

         `verify_offset` is an applied offset, so it is a batch boundary; assert this.
      8. assert cross-partition consistency (`outbox_next_seq[A→B] > inbound_seen_B[A]` per pair, Pitfall 1);
      9. return the report: cut_at_ms, per-partition offsets and hashes, durations.

      Fail points: `restore::after_meta`, `restore::mid_partition`. A crash mid-restore leaves a dir that the next restore refuses (non-empty) with a clear "delete and retry" message.
    - Takeover: a restored node keeps uploading to the same prefix only if started with `[backup] takeover = true` / `--takeover` (fence semantics, 08-13). Otherwise the operator configures a new prefix. Document this.
    - `archive::pack_dir(local_layout_dir, w: impl Write)` and `archive::unpack(r, dir)` handle tar (no absolute paths, no `..`, regular files only). `RestoreSource::Tar(path)` unpacks to a temp dir and restores through the same LocalFs path.
    - Online backup (`control/admin.rs`, replacing the 08-10 stub): create a temp dir LocalFs store, force a fresh snapshot per partition (Node snapshot trigger from 08-09, or export directly), run one `Uploader::round` against it with a fresh fence ident, then stream `pack_dir` as `application/x-tar`, and remove the temp dir.
    - Offline backup: `backup_offline(data_dir, out)` opens the Node in Inspect mode, then does the same round into a temp LocalFs, then packs.
    - Tests (LocalFs, tempdirs):
      - a workload across 4 partitions with children/signals, upload rounds, then restore at current → digests equal the source's digests at the cut (re-computed by an Inspect open of the source truncated at cut), and the state_hash check passes;
      - `--at` an older gen → consistent at that cut;
      - tamper one chunk byte → chain error naming the partition;
      - tamper a snapshot → sha error;
      - a hand-built manifest with `snapshot_offset > cut_offset` (or `verify_offset > cut_offset`) → `BadManifest`, nothing written beyond the refusal;
      - a chain that starts at a snapshot after trimming (the 08-13 chain_start case b) restores correctly;
      - a non-empty dir is refused;
      - tar round trip (online + offline) → identical digests.
  </behavior>
