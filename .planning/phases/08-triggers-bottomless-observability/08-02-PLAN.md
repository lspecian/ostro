<interfaces>
From research Pattern 2 (adopted as P8-D1):
```
Header (64 B, LE): magic "OSNP" u32 | snap_ver u16 = 1 | flags u16 (bit0 = lz4 frames) | partition u16 | partition_count u16
                   | state_format u32 | applied_offset u64 (exclusive) | latest_epoch u32 | created_at_ms u64 | reserved [u8;16]=0 | header_crc32c u32
Frame: u32 LE len | u8 kind | payload | u32 LE crc32c(kind ‖ payload)
  1 TableBegin{u16 name_len,name} 2 Rows{(u32 klen,key,u32 vlen,value)*} (≤1 MiB uncompressed) 3 TableEnd{u64 row_count}
  4 BlobRefs{u32 n,[sha256;n] sorted dedup} 5 Trailer{[32] logical_digest,[32] state_hash,u64 total_rows,u64 frames}
  unknown kind < 128 -> error; >= 128 -> skip
```
fjall 3.1.13: `Database::snapshot()` is cross-keyspace and batch-atomic (one seqno per batch). `Keyspace::start_ingestion()` writes tables directly. Meta `checkpointed_offset` is excluded from both the export and the digest. Install writes it as `applied_offset`.
</interfaces>

  <name>Task 1: Blob-ref visitor + OSNP v1 writer/reader + export_snapshot</name>
  <files>crates/ostro-partition/src/store/blobrefs.rs, crates/ostro-partition/src/store/snapshot.rs, crates/ostro-partition/src/store/digest.rs, crates/ostro-partition/tests/blobrefs.rs, crates/ostro-partition/tests/snapshot.rs</files>
  <behavior>
    - `blobrefs::visit_row(table: Table, key: &[u8], value: &[u8], out: &mut Vec<[u8;32]>) -> Result<(), StoreError>` uses an **exhaustive `match table`** with no `_` arm, so a new keyspace fails to compile until its refs are declared. For each table, document where PayloadRefs live (payloads rows, run input/result refs, outbox msgs, inbox signal payloads, …); tables with none push nothing. It reads only prost `PayloadRef` fields or documented postcard values (F5).
    - `PartitionStore::blob_refs_snapshot() -> Result<BTreeSet<[u8;32]>>` collects every ref of the current state from one fjall snapshot. 08-19 GC uses it.
    - Writer → reader round trip: frames decode in order, row counts match, the trailer digest equals `store.digest()` of the source, and `state_hash`/`applied_offset` equal the source meta.
    - The lz4 flag (bit0) round-trips. Default off; document why (measure the size ratio and report it).
    - Corruption: for a small store, flipping each byte position of the encoded file → the reader returns `SnapshotError::{HeaderCrc, FrameCrc, Truncated, UnknownFrame, DigestMismatch}`, never a panic or a silent success (proptest over positions; ≥ 256 cases).
    - Unknown frame kind 200 inserted by a test writer → skipped. Kind 9 → error.
    - Concurrent export: a thread applies chunks continuously while another exports 20 times. Each export's rows, re-imported, give `digest()` equal to the digest computed by replaying the log up to that export's `applied_offset`.
  </behavior>
  <action>
- Refactor `store/digest.rs` minimally so the digest is a reusable incremental builder (`DigestBuilder::{table_begin, row, table_end, finish}`). The existing `digest()` uses the builder, and its output must stay byte-identical: the existing store_digest tests and per-table digests (05-12 format corpus) pin it.
- In `snapshot.rs`, implement `export_snapshot<W: Write>(&self, w: W, created_at_ms: u64) -> Result<SnapshotInfo, SnapshotError>` per research "Code Examples":
  - one `self.db.snapshot()`;
  - read meta from that snapshot;
  - iterate `TABLES`, skipping `K_CHECKPOINTED`;
  - feed every row to the writer, the digest builder and the blob visitor;
  - emit Rows frames of ≤ 1 MiB, then BlobRefs, then Trailer.
- `SnapshotInfo { applied_offset, state_hash, latest_epoch, logical_digest, total_rows, bytes, blob_refs: Vec<[u8;32]> }`.
- `state_format` = the store's current STATE_FORMAT/VALUE_FORMAT constant. Readers accept `state_format ≤ current` and route older values through a `migrate_row(table, from_format, key, value)` hook that today is the identity for the single format; the D18-amended rule is documented in code. A newer `state_format` → `SnapshotError::FutureFormat`.
- `OsnpReader<R: Read>` streams frames, so the Phase 12 transport can forward frame by frame. Expose `next_frame()`.

  <name>Task 2: Staged install (ingestion spike with WriteBatch fallback) + docs/snapshot-format.md</name>
  <files>crates/ostro-partition/src/store/snapshot.rs, crates/ostro-partition/tests/snapshot.rs, docs/snapshot-format.md</files>
  <behavior>
    - `install_snapshot(state_root: &Path, partition: u16, cfg: &StoreConfig, r: impl Read) -> Result<SnapshotInfo, SnapshotError>`:
      1. builds `state/.install-pNNNN` (removing any leftover first);
      2. ingests the tables, meta last, through a WriteBatch with `persist(SyncAll)`;
      3. closes, reopens and checks `digest() == trailer.logical_digest` and `applied_offset == header.applied_offset`;
      4. renames any existing `state/pNNNN` to `state/.old-pNNNN`, renames staging to `state/pNNNN`, fsyncs `state/`, and removes the old directory.
    - Crash safety: an injected failure after each step (test-only hook or `fail` points `snapshot::install_before_swap` / `snapshot::install_after_old_rename` under the `failpoints` feature) leaves either the old state intact or the new state complete. A reopen after a "crash" never sees a half-installed directory, and a leftover `.old-pNNNN` with no `pNNNN` is recovered by renaming it back. Document this recovery rule.
    - Installing on a partition with a different `partition_count` → `SnapshotError::Mismatch`.
    - Rebuild equivalence: export at random applied offsets k of a generated workload, install, replay `[k, end)` → digest equals the full-replay digest (proptest, 32 cases; reuses the existing rebuild_digest generators through `tests/common`, read-only).
  </behavior>
