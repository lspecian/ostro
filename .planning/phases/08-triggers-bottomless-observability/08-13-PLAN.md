  <name>Task 1: HookIngress: verify → extract → act (start / signal / complete_token) + Slack challenge + metrics</name>
  <files>crates/ostro-server/src/control/webhooks.rs, crates/ostro-server/tests/webhooks.rs</files>
  <behavior>
    - Unknown hook → 404 (no timing difference beyond a constant lookup).
    - Verify with the meta-configured verifier and the resolved secret; `now` comes from the server clock (FakeClock in tests). Malformed / MissingHeader / BadSignature → 401; Stale → 401 with `stale` in the JSON error; Config → 500. In every failure case no command is submitted (assert via the partition command counters or `runs ls` count).
    - The Slack `url_verification` body (only after verification) → 200 `text/plain` with the challenge.
    - Delivery key: the configured extractor, or the vendor default. For `none`, a key derived from `sha256(body)` keeps the dedupe meaningful (documented). For Slack, a request with `X-Slack-Retry-Num` uses the same key.
    - start: `StartRun{workflow, version?, input: InputSelector, idempotency_key: "hook/<name>/<key>", ConflictPolicy::ReturnExisting, traceparent from the request header if present}` → 200 `{run_id, created: bool}` after apply.
    - signal: resolve the run id (pointer to a run id string, or `(workflow, idempotency pointer)` → the run whose idempotency key is `hook/<start-hook>/<value>` via the existing idempotency lookup) → `SignalRun{name, payload: body or pointer, request_id: key}` → 200 after apply. Run not found → 404 (no retry storm: document that providers retry 404s).
    - complete_token: pointer → token → `CompleteToken` → 200.
    - The body limit is enforced by the router (413, from 08-09).
    - Metric `ostro_webhook_requests_total{hook,outcome}`, with outcomes ok, duplicate, unauthorized, not_found, error. Hook names are operator-defined and bounded by meta.
    - Tests: per verifier kind, a valid request starts a run; a duplicate with the same delivery key → same run id, `created=false`, one run total; a tampered body → 401 and no run; a stale Stripe timestamp → 401; Slack challenge echoed; the signal action delivers to a waiting run, and a redelivered signal (same key) is applied once (SignalSeen); complete_token completes an await-token guest (if a Phase 5 tokens guest exists; otherwise assert command acceptance).
  </behavior>
