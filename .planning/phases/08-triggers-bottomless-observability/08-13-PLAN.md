<task type="auto" tdd="true">
  <name>Task 2: OSEG chunks, manifest, LOCK fencing, Uploader::round + loop, upload floor, remote retention</name>
  <files>crates/ostro-backup/src/{chunk,manifest,fence,uploader}.rs, crates/ostro-backup/tests/common/mod.rs, crates/ostro-backup/tests/{uploader,cut_consistency,fencing}.rs</files>
  <behavior>
    - `chunk`: encode/decode OSEG v1. `verify_chain(prev_sha, chunks)` checks prev links, `base == prev.end`, non-decreasing epochs, each envelope's CRC32C (via the ostro-types envelope decoder) and the trailer sha. Corruption tests cover the header, body, trailer and chain break.
    - `manifest`: postcard + sha256 trailer, `prev_manifest_sha256` linking, `manifest/current` and `manifest/gen/<gen 20d>`.
    - `fence`:
      - `acquire(store, ident{cluster_id,node_id,incarnation}, takeover)`: PUT `LOCK` with If-None-Match → Ok; if it exists with the same ident → Ok; with a different ident and `takeover` → overwrite via If-Match on its etag; otherwise `Fenced`;
      - `check_before_manifest` is a no-op when conditional PUT is supported, else it re-reads LOCK and compares (the fallback).
    - `Uploader::round(&self, store) -> RoundReport` performs steps 1–5 of research Pattern 5:
      1. `cut = node.log_cut()`;
      2. upload blobs that are pending (observer + startup reconcile via `list("blobs/")`);
      3. per partition, chunks `[uploaded_end_p, cut_p)` split at epoch boundaries, ≤ 8 MiB per chunk;
      4. any new local snapshot (from `snapshot_events` / the dir scan) → `p/<pppp>/snap/<applied 20d>-<sha256>.osnap` (multipart when ≥ 64 MiB);
      5. the meta snapshot if the meta applied index changed, captured after step 1;
      6. the manifest with `If-Match` on the previous etag (fail point `upload::before_manifest`), including `verify_offset`/`verify_state_hash` = the (applied, state_hash) observed with applied ≤ cut.

      On `PreconditionFailed`: stop and set `ostro_backup_fenced = 1`. After a durable manifest: set `upload_floor_p = min(latest uploaded snapshot offset, uploaded chunk end)` via `floor_handles`. Then remote retention: keep the last `remote_snapshots_keep` snapshots per partition and the chunks with `end > oldest kept snapshot offset`; delete older ones (and old gen manifests beyond the kept snapshot rounds).
    - The loop runs every `seal_interval`; idle partitions upload nothing. Metrics: `ostro_backup_cut_age_seconds`, `ostro_backup_upload_bytes_total{kind}`, `ostro_backup_failures_total{kind}`, `ostro_backup_fenced`. Failures back off and never block apply.
    - Tests on LocalFs (`tests/common` builds a Node + LocalFs store in a tempdir):
      - `uploader`: only below HW (chunk end ≤ cut ≤ HW); barrier closed / Inspect mode → zero objects; keys and epoch split after a forced epoch bump; blobs present before any chunk referencing them; meta snapshot after the cut; snapshots uploaded; the upload floor caps trimming.
      - `cut_consistency` (proptest, 24 cases): a cross-partition children/signals workload; after each round, simulate "restore at this manifest" with an in-test minimal restore (truncate each partition's log at `cut_p` in a copy and rebuild) → for every pair (A, B), `outbox_next_seq[A→B]` and `inbound_seen_B[A]` are consistent, so no message is lost or dedupe-dropped.
      - `fencing`: two uploaders with different incarnations on one prefix → the second is fenced and its metric is set; `takeover` works; the fallback path (conditional disabled) detects a LOCK change. A MinIO variant is env-gated on the `OSTRO_TEST_S3_*` variables (Phase 6 convention).
  </behavior>
