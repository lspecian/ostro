<task type="auto" tdd="true">
  <name>Task 1: BlobStore mtime touch + GC lock + sweep with grace + failpoint</name>
  <files>crates/ostro-blob/src/lib.rs, crates/ostro-blob/src/gc.rs, crates/ostro-blob/tests/gc.rs, crates/ostro-blob/tests/blob_failpoints.rs</files>
  <behavior>
    - `put` on an existing blob calls `File::set_modified(now)` (opened for write without truncation; content is never rewritten) and still notifies `subscribe_puts`.
    - `put` holds `gc_lock.read()`; `sweep` holds `gc_lock.write()` only during the unlink pass, not during the mark.
    - `sweep(mark: &HashSet<[u8;32]>, older_than: SystemTime) -> SweepReport { scanned, deleted, kept_marked, kept_young, bytes_freed, deleted_shas }`. It walks `blobs/<hh>/` and, for each file with a valid sha name, deletes it if it is not in the mark and `mtime < older_than`. Fail point `blobgc::before_unlink`. Unknown files are left alone and logged once.
    - Tests:
      - an unreferenced old blob is deleted;
      - an unreferenced young blob is kept;
      - a referenced old blob is kept;
      - re-putting an old blob before the sweep keeps it (the mtime was touched);
      - concurrency: a sweep and puts of the same sha racing for 1,000 iterations → after every iteration, a blob whose put returned Ok before the sweep's write lock was taken exists (the put happens-before) or is re-creatable. Assert directly that **a put which completes after the mark but before the sweep never ends with the blob missing**;
      - failpoint (single-threaded): panic at `before_unlink` → the store reopens fine, nothing referenced is lost, and a rerun completes.
  </behavior>
  <action>
Implement in a new `gc.rs` module (declared in ostro-blob lib.rs). Use `std::sync::RwLock` or `parking_lot` if already a dependency; otherwise std.
  </action>
