  <name>Task 1: ScheduleFire apply: validation, watermark, start, manual, overlap policies</name>
  <files>crates/ostro-partition/src/apply/schedule.rs, crates/ostro-partition/src/apply/mod.rs, crates/ostro-partition/tests/apply_schedule.rs</files>
  <behavior>
    - Validation → `Rejected(Invalid(BadScheduleFire))` when:
      - the name is empty or > 256 bytes;
      - `fire_time_ms == 0`;
      - Fire/Manual has no `start`, or Advance has one;
      - Manual has an empty `request_id` or one > 64 bytes;
      - `start.idempotency_key` differs from the `cron_idempotency_key` for (schedule, fire_time) (or the manual form);
      - `overlap` is out of range.

      `schedule_owner(schedule, P) != this partition` → `Invalid(ScheduleOwnerMismatch)`. A start whose run id routes elsewhere → the existing `WrongPartition`.
    - **Schedule incarnation (W4):** before any other rule, if a `schedule_state` row exists and its `schedule_created_at_ms` differs from the command's `schedule_created_at_ms`, the row belongs to a deleted schedule with the same name. Reset it in the same batch: watermark 0, `last_run = None`, `buffered = None`, counters 0, the new `schedule_created_at_ms`. Then delete any `0x02‖run` reverse rows pointing at it lazily: on_run_terminal ignores a reverse row whose schedule row has a different incarnation than the one recorded at start, so store `schedule_created_at_ms` in `ScheduleRunRow` too. An older incarnation in the command than in the row (a stale in-flight fire) → Duplicate, no reset.
    - Fire with `fire_time_ms <= watermark` → `ApplyOutcome::Duplicate { existing }` (the existing duplicate outcome used by idempotent StartRun; `existing` = the schedule's `last_run` if set, else the run found under the fire's `__cron/` idempotency key, else none), with `duplicates += 1` and no start. Advance with `fire_time <= watermark` → the same Duplicate outcome with no `existing`. If `ApplyOutcome::Duplicate` cannot carry `None`, use the closest existing accepted-duplicate form and record it in the SUMMARY; never invent a new outcome code.
    - Fire with `fire_time > watermark` and `last_run` absent or terminal → start the run via the internal StartRun path (ConflictPolicy::ReturnExisting; the idempotency row is the second guard). Set `last_run = run`, `watermark = fire_time` and `fired += 1`, and write the `0x02‖run → schedule` reverse row, all in the same batch.
    - Overlap when `last_run` is non-terminal:
      - Skip → `watermark = fire_time`, `skipped += 1`, no start.
      - BufferOne → `buffered = Some(fire)` (replacing an older buffered fire, `skipped += 1` for the replaced one), `watermark = fire_time`.
      - AllowAll → start (as above).
      - CancelOther → internal RequestCancel of last_run (graceful, D3 semantics), then start.
      - TerminateOther → internal TerminateRun, then start.
    - Advance (catch-up Skip) → `watermark = max(watermark, fire_time)`, `skipped += skipped_field`.
    - Manual → start regardless of the watermark (the overlap policy still applies against last_run). The watermark is unchanged. The idempotency key is the manual form, so a repeated request_id → ReturnExisting.
    - Every outcome is deterministic and folded into the state hash like other outcomes.
  </behavior>

      - delete the reverse row;
