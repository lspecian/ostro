<feature>
  <name>Webhook signature verifiers and idempotency extractors</name>
  <files>crates/ostro-triggers/src/webhook.rs, crates/ostro-triggers/src/extract.rs, crates/ostro-triggers/tests/webhook_verify.rs</files>
  <behavior>
    `verify(spec: &VerifierSpec, secret: &[u8], headers: &[(String, Vec<u8>)] /* lower-cased names */, body: &[u8], now_unix: i64) -> Result<VerifiedDelivery, HookError>`. `HookError` is one of `Malformed`, `MissingHeader(&'static str)`, `Stale`, `BadSignature`, `Config`.

    Vectors (re-verify the recalled vendor vectors while implementing; if a recalled vector is wrong, compute the expected value independently with a second implementation in the test, e.g. sha2+hmac by hand, and note it in the SUMMARY):
    - GitHub: secret `It's a Secret to Everybody`, body `Hello, World!` → header `sha256=757107ea0eb2509fc211221cce984b8a37570b6d7586c22c46f4379c8b043e17` accepted; one flipped body byte rejected; missing `sha256=` prefix → Malformed.
    - Slack: the docs example (`v0=a2114d57b48eac39b9ad189dd8316235a7b4a8d21a10bd27519666489c69b503`, timestamp `1531420618`, the documented body) is accepted at now = ts. now = ts + 301 → Stale. `{"type":"url_verification","challenge":"x"}` → `slack_challenge(body) == Some("x")`.
    - Stripe, computed in-test:
      - `t=<now>,v1=<good>` → ok;
      - `t=<now>,v1=<bad>,v1=<good>` → ok (rotation);
      - `t=…,v0=…,secret=…,destination=…,payload=…,v1=<good>` → ok, and the unknown entries are never used;
      - `|now−t| > tolerance` → Stale;
      - no `t` → Malformed;
      - only `v0` → BadSignature;
      - the endpoint secret `whsec_…` is used as-is (not base64-decoded).
    - Standard Webhooks:
      - secret `whsec_<base64>` is decoded;
      - signed content is `"{id}.{ts}.{body}"`;
      - the header `webhook-signature: v1,<b64> v1,<b64>` accepts any match;
      - stale → Stale.
    - Generic HMAC:
      - configurable header name, optional prefix (`sha256=`), algorithm sha256 (default) or sha1 (opt-in `legacy_sha1`), encoding hex or base64;
      - optional timestamp header + template `{ts}.{body}` or `{body}`, with optional tolerance;
      - each combination is covered by one test.
    - All comparisons go through `Mac::verify_slice`. A grep-based test asserts that `webhook.rs` contains no `==` between signature byte slices or strings.

    Extractors (`extract.rs`):
    - `IdempotencyExtractor::parse("header:X-GitHub-Delivery" | "json:/data/object/id" | "none")`;
    - `extract(&headers, body) -> Result<Option<String>, ExtractError>`. The JSON pointer is applied to `serde_json::from_slice(body)` **only after** verification, which callers enforce by taking a `VerifiedDelivery` token. Keys longer than 256 bytes → error;
    - `default_for(kind)` returns the vendor default;
    - `InputSelector::{Body, JsonPointer(String)}` produces the run input bytes.
  </behavior>
  <implementation>
- `VerifiedDelivery` is a zero-size proof-of-verification token. Extractors and `InputSelector` take `&VerifiedDelivery`, so the type system enforces verify-before-parse.
- Secrets are borrowed `&[u8]` and never logged. The error `Display` never includes the header value.
  </implementation>
