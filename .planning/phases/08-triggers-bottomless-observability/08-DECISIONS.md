# Phase 8 decisions (adopted defaults; user may override)

**Status:** adopted by the planner on 2026-11-19. The project runs in YOLO + auto_advance mode, so there is no blocking decision checkpoint. Every recommendation in `08-RESEARCH.md` (commit e757400) was adopted, plus the orchestrator's directives. Plan 08-01 Task 1 copies each decision into `.planning/STATE.md` § Decisions by hand and adds the user-review items to § Pending Todos.

**User-review items** (08-01 flags them in STATE.md Pending Todos):
- P8-D9: croner behind a jiff-0.2 adapter. This puts a second jiff major in the graph until croner ships jiff 1 support.
- P8-D3: the seal interval default of 1 s. At P=16 with every partition busy, that is about $7/day in S3 PUTs. The cost table is in docs/bottomless.md.
- P8-D11: Kafka/Chronik topic-consumer triggers are out of scope (no requirement names them).
- P8-D16: the per-run guest-log lifetime cap is held in memory only and resets on restart.
- P8-D21: 22 plans instead of the research's 18 (API surface consolidated; CLI, bottomless primitives and SC5 e2e split out after the plan check).

An override can be folded into any plan that has not started yet. Ordinals already shipped in code follow RESERVATIONS.md rule 3: they are never reused or renumbered.

| P8-D1 | Snapshot format | **Logical OSNP v1** (research Pattern 2), exported from **one** fjall `Database::snapshot()` (batch-atomic, so the apply thread is never paused). Layout: 64-byte header (magic `OSNP`, `snap_ver` 1, flags bit0 = lz4 frames, partition, partition_count, `state_format`, `applied_offset`, `latest_epoch`, `created_at_ms`, header CRC32C). Then CRC32C frames: TableBegin/Rows/TableEnd/BlobRefs/Trailer; unknown kinds ≥ 128 are skippable. The trailer `logical_digest` uses exactly the `store/digest.rs` layout. Local files: `snapshots/pNNNN/<applied 20d>.osnap` (+ `.blobrefs` cache). Install = staged dir `state/.install-pNNNN` + `start_ingestion` per table (fallback: ~4 MiB WriteBatch chunks), meta last, reopen + digest check, atomic dir rename, fsync `state/`. **Physical fjall copies are rejected.** Per D18 (amended), snapshot rows become a source of truth once trimming starts: the header carries `state_format`, readers accept every older format, and every later STATE/VALUE_FORMAT change ships a row migrator. Phase 12 follower install streams the same bytes. | 08-02 (format), 08-09 (service + install on open), 08-22 (docs freeze-ready) |
| P8-D2 | Trim floor | `floor = min(force_checkpoint(), local_floor, upload_floor?, retention_floor?)`. `local_floor` = `applied_offset` of the **oldest retained** local snapshot (keep 2). `upload_floor` applies only when bottomless is on. Each floor is a `tokio::sync::watch` channel. The floor is published only after the snapshot file fsync, rename and dir fsync. Invariant (SC4): `log_start ≤ oldest retained snapshot applied_offset`. No usable snapshot below log_start → the partition fails with "snapshot required: run `ostro restore`". No auto-fetch from remote. | 08-01 (config contract), 08-09 (implementation), 08-13 (feeds upload_floor) |
| P8-D3 | Bottomless upload | One node-level uploader (leader services only, after every barrier opens). Every `seal_interval` (default **1 s**): take an **HwVector consistent cut**; upload blobs first; then per-partition **uploader-sealed** OSEG v1 chunks of raw OSTR envelopes, split at epoch boundaries and hash-chained (`prev_chunk_sha256`), keyed `p/<pppp>/seg/<epoch 10d>-<base 20d>-<end 20d>.oseg`; then a meta snapshot `meta/<index 20d>.msnap` (captured after the cut); then `manifest/current` (If-Match), with an immutable `manifest/gen/<gen 20d>` copy on every snapshot round. Snapshots go to `p/<pppp>/snap/<applied 20d>-<sha256>.osnap`. Remote retention keeps K=3 snapshots per partition plus every chunk with end > the oldest kept snapshot. Idle partitions upload nothing. **"Sealed" means closed by the uploader at a tick and never appended to afterwards** (documented interpretation of BACK-01). seg/ and snap/ objects are immutable, written with `put_if_absent` (same sha = success, different sha = fenced). **Chain start:** on a fresh prefix, or when `uploaded_end < log_start`, the newest local snapshot S is uploaded first and the chain starts at S (offset 0 only with no snapshot and log_start 0). **Snapshot hold-back:** a manifest references only snapshots with `snapshot_offset ≤ cut_p`; `Manifest::validate()` enforces `snapshot_offset ≤ verify_offset ≤ cut_offset`. With backup enabled, `Node::open` initialises the upload floor to `Some(log_start)` before retention starts. | 08-08 (primitives), 08-09 (floor init), 08-13 |
| P8-D4 | Prefix fencing | A `LOCK` object `{cluster_id, node_id, incarnation}` created with `If-None-Match: *`, and the manifest PUT with `If-Match: <etag>`. A failed precondition stops uploads, sets `ostro_backup_fenced = 1` and logs an error. `incarnation` is a new additive `node.toml` key (F6: unknown keys are ignored). A restored node gets a new incarnation and must pass `--takeover` to upload to the same prefix. **Fallback** for providers without conditional PUT: re-read LOCK before every manifest PUT and compare the incarnation, documented as weaker. **Scope (Phase 12 F12c):** LOCK and the single manifest writer are single-node constructs. Cluster-wide bottomless restore is deferred; Phase 12 does per-partition chain repair only (per-partition writer fencing by leader epoch). Restore walks the chain back from the manifest head (F12b), and the HwVector is updated at the single HW publication point `publish_hw` (F12a). | 08-03 (put_if_absent/put_if_match), 08-13 |
