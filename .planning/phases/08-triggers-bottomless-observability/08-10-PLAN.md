<interfaces>
The meta records (05-07) are the persisted shapes. DTOs mirror them in API-friendly form:
- `ScheduleDto { name, workflow, version?, cron, timezone, input (json or base64), paused, overlap: "skip"|"buffer_one"|"allow_all"|"cancel_other"|"terminate_other", catchup: "skip"|"one"|"all", catchup_window, start_at?, end_at?, version_tag (meta version for CAS), next_fire_at? (computed by server), last_fire_at? }`
- `WebhookDto { name, action: {start{workflow, version?, input: "body"|json-pointer} | signal{workflow, run_by: {run_id_pointer}|{idempotency_pointer}, name} | complete_token{token_pointer}}, verifier: {kind: "stripe"|"github"|"slack"|"standard"|"hmac", secret_ref, tolerance?, header?, prefix?, algorithm?, encoding?, timestamp_header?, template?}, idempotency: "header:X"|"json:/p"|"none"|default, version_tag }`. Secrets are never returned: `secret_ref` names a sealed secret.
- `HookResponse { status: u16, body: Bytes, content_type }`, so a Slack challenge can echo plain text.
- `RunLogLine { ts_ms, level, message, fields: serde_json::Value, attempt }`
- `AdminApi::backup_stream() -> impl Stream<Item = Result<Bytes>>` (tar, `application/x-tar`).
Mapping for overlap/catchup strings ↔ meta u8: use exactly 05-07's constants (via the ostro-triggers `OverlapPolicy`/`CatchupPolicy` TryFrom from 08-05 if available; otherwise duplicate the table with a test cross-checking the meta constants).
</interfaces>
