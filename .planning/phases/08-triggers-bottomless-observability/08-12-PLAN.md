<task type="auto" tdd="true">
  <name>Task 1: Owner-partition cron driver (leader service) with catch-up</name>
  <files>crates/ostro-partition/src/leader/cron.rs, crates/ostro-partition/src/leader/mod.rs, crates/ostro-partition/tests/cron_driver.rs</files>
  <behavior>
    - `leader::spawn_all` starts the cron driver for each partition when `NodeConfig.schedule_source` is Some. The driver filters specs with `schedule_owner(name, P) == self.partition` and skips paused ones.
    - On start (leadership): for each owned schedule, read its watermark from schedule_state (0 when absent; then treat `created_at_ms` as the floor so a new schedule never back-fills), compute `fires_between(wm, now, cap)`, and apply `select_catchup`:
      - the Advance fire → `ScheduleFire{kind: Advance, fire_time: advance_to, skipped}`;
      - each fire in `fire` → `ScheduleFire{kind: Fire}`.
    - Steady state: a `BTreeMap<(due_ms, name)>` window. Sleep until the earliest due on the injected clock (with a watch on the source and on shutdown). At due time, build the StartRun (run id routed to this partition via the owner-partition run-id helper, workflow/version/input from the spec, idempotency key `cron_idempotency_key`, tags `ostro.schedule=<name>`), submit `ScheduleFire{kind: Fire, overlap: spec.overlap}`, then compute the next fire.
    - Spec changes (watch) re-plan that schedule. A cron or timezone change applies to future fires only; the watermark keeps exactly-once.
    - Resume (paused → false) runs the catch-up path for that schedule.
    - Submit failures (NotLeader, Fenced) stop the driver (it is a leader service). Transient errors retry with backoff and the same command (idempotent by watermark + key).
    - Metric `ostro_cron_fires_total{schedule,outcome}` is incremented from the apply outcome detail (started/skipped/buffered/duplicate).
    - Tests (FakeClock, single node P=4):
      - a `*/10 * * * * *` UTC schedule produces fires at each 10 s boundary with one run each;
      - kill and restart the node between fires several times (copy_dir pattern) → every fire_time has exactly one run, and catch-up follows policy One after a simulated 5-minute downtime;
      - Skip after downtime → zero catch-up runs and the watermark is advanced;
      - All with window 60 s and cap 3 → exactly 3;
      - a non-owner partition never submits.
  </behavior>
  <action>
Model the window on `leader/timers.rs` (02-14 pattern). Keep the submit path identical to other leader services (same handle and ack semantics).
  </action>

  </verify>
  <done>The owner-only driver fires on time in the schedule's timezone, catches up per policy after downtime, and stays exactly-once across restarts.</done>
