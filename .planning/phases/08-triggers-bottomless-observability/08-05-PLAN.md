  <behavior>
    Spike first (RED can be a compile test): confirm `jiff02::tz::TimeZone::tzif(name, bytes)` and `jiff::tz::TimeZone::tzif(name, bytes)` exist with those shapes, and that `croner::Cron::new(expr).with_seconds_optional().parse()` + `find_next_occurrence(&jiff02::Zoned, false)` compile under the jiff feature. If a shape differs, adapt the adapter and record it in the SUMMARY. If jiff02 has no bytes constructor, enable nothing new; use the closest API with the same bundled-bytes source, and document how equality of the rules is ensured.

    Cases (`expr`, tz, after (local time) → expected next, UTC):
    - `0 30 2 * * *`, America/New_York, 2026-03-08 00:00 → 2026-03-09 02:30 EDT. 02:30 does not exist on 03-08, so there is no fire that day (croner 4.0.3 DST-gap rule; assert whatever croner documents and pin it).
    - `0 30 1 * * *`, America/New_York, 2026-11-01 00:00 → exactly one fire at 01:30 EDT (first occurrence). The next is 2026-11-02 01:30 EST.
    - `0 0 2 * * *`, Europe/Berlin, around 2026-03-29 and 2026-10-25: same gap/overlap assertions.
    - `0 15 2 * * *`, Australia/Lord_Howe, 30-minute DST shift on 2026-10-04: pinned.
    - Seconds field `*/15 * * * * *`, `L` (`0 0 0 L * *`), `#` (`0 0 9 * * MON#2`), `W` (`0 0 9 15W * *`).
    - UTC and the empty timezone (default "UTC").
    - Errors: invalid expression → `CronError::Expr`; unknown tz `Mars/Base` → `CronError::Timezone`; `end_at_ms < start_at_ms` → `CronError::Bounds`.
    - `fires_between(spec, wm, now, cap)` returns increasing `Vec<i64>` within `(wm, now]` and inside [start_at, end_at]; it is truncated at `cap` and reports `truncated: bool`.
    - `select_catchup(policy, fires, window_ms, now)`:
      - Skip → `Advance` to the last fire;
      - One → `[last]`;
      - All → those within `now - window`, capped.

      Pin the return type as `CatchupPlan { fire: Vec<i64>, advance_to: Option<i64>, skipped: u32 }`.
    - Proptest (512 cases): random expr from a small grammar × tz from {UTC, NY, Berlin, Lord_Howe, Kolkata} × random after → `next_after` is strictly increasing when iterated 50 times, and `fires_between` equals the iterated `next_after` sequence.
  </behavior>
