<design_decision>
Apply cannot interpret Phase 3's journal events (their semantics are not defined yet and Phase 3 runs in parallel). So `EventsAppended` carries the opaque events PLUS an explicit list of Phase-2-owned `Derived` intents computed by the submitter (the engine host in Phase 4). Apply validates fencing and applies events and intents atomically. Because both are in the log, replay stays deterministic. Phase 4 may later move derivation into apply additively (new fields/variants). Record this in the SUMMARY and in a module doc comment. `StartRun.rng_seed` (32 bytes, generated by the submitter) is carried and stored so Phase 3's `RunStarted.rng_seed` has a home; Phase 3 owns its semantics.
Phase 3 coordination: re-read lib.rs before editing; only add `pub mod command;` + re-exports; never touch `journal.rs`.
</design_decision>
