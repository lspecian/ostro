</interfaces>

<algorithm>
State: `in_flight: BTreeSet<u16>` targets with an outstanding delivery; a `JoinSet` of delivery futures; per-target backoff (50 ms doubling to 1 s).
Loop until shutdown:
1. For each target t (0..P) not in flight and not backing off: `rows = reader.prefix(Outbox, outbox_prefix(t), max_batch_msgs)` (ascending seq; truncated rows are already deleted). If non-empty: decode rows into `InboundMsg{seq, msg}`, spawn `router.deliver(t, InboundBatch{src: self, msgs})`, mark in flight.
2. Wait on (a) any delivery completion, (b) an `Action::OutboxAppended` from `handle.machine().subscribe_actions()` (handle `Lagged` by doing a full rescan), (c) `idle_poll` tick, (d) shutdown.
3. On completion for t: `Ok(Accepted | Duplicate)` → `handle.submit_one(OutboxTruncated{target: t, upto_seq: last seq of that batch})` (Accepted or Duplicate are both fine; Err → partition is failing, exit), clear in-flight, reset backoff. `Ok(Rejected(SeqGap{..}))` → log `error!` (should be impossible: we always send from the lowest untruncated seq), back off and retry from a fresh read. `Err(_)` (target down, ack lost) → back off and resend the same rows later — the target's `inbound_seen` dedupes.
Never send a second batch to t while one is in flight. Restart/leadership change: the task is recreated by Node and restarts from the table (re-sends expected). Metrics: `ostro_shuffler_batches_total{src,target}`, `ostro_shuffler_retries_total`, gauge `ostro_outbox_rows` per partition (approximate via last read size).
</algorithm>
