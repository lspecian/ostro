<feature>
  <name>Hash-chained audit journal with fail-closed group commit</name>
  <files>crates/ostro-server/src/audit/{journal,segment,chain,writer,verify,export}.rs, crates/ostro-server/tests/{audit_journal,audit_crash}.rs</files>
  <behavior>
    Record (`journal.rs`): `{v:1, seq, ts_ms, node, incarnation, actor, actor_kind, tenant, action, target, outcome, request_id, details, count?, first_ts_ms?, last_ts_ms?, prev_hash, hash}`; canonical JSON = keys in fixed order, no whitespace, UTF-8, `hash` omitted; `hash = hex(sha256(prev_hash_bytes ‖ canonical))`. Genesis `prev_hash = sha256("ostro-audit-genesis" ‖ node ‖ incarnation)`. Control records: `segment_open{prev_segment_last_hash}`, `audit_recovered{truncated_bytes, last_good_seq}`, `retention_trim{first_kept_seq, first_kept_hash}`.
    Cases:
    - append 1,000 records → verify OK; flip one byte / delete a line / swap two lines / insert a forged line → verify fails naming the first bad seq.
    - rotation at a small `segment_bytes` (4 KiB in tests) → several files, each starting with `segment_open`; chain verifies across files; files are named `audit-<seq 20 digits>.jsonl` by first seq.
    - torn tail (truncate the last line mid-way, or append garbage) → open truncates to the last newline-terminated valid record, appends `audit_recovered`, verify OK.
    - writer: `reserve()` returns a permit within `reserve_timeout`; `commit(ev)` resolves after fsync; 32 concurrent committers are batched (fewer fsyncs than records, asserted through a counter); `audit::writer_stall` failpoint or a full queue → reserve fails with `AuditUnavailable` after the timeout and nothing is written; a commit error (fsync EIO via `audit::before_fsync`) poisons the writer: subsequent reserves fail (fail closed) until restart.
    - coalesced events (`record_coalesced`) are buffered by key and flushed as one record with `count` at window end (window from `[audit] secret_coalesce`, injected clock) and on `flush()`.
    - retention: segments wholly older than `retention` or beyond `max_bytes` (oldest first, never the active segment) are deleted after appending `retention_trim`; verify starts from the anchor.
    - `verify_dir(path) -> Result<VerifyReport{records, segments, first_seq, last_seq, last_hash}, VerifyError{seq, reason}>`; `ostro audit verify --data-dir` (CLI wiring is 14-18) uses it.
    - chain-head export (W8): every `[audit] head_export_interval` (default 1 h, injected clock) and at shutdown the writer emits the current `(node, incarnation, seq, hash)` as a `chain_head` log line, an OTLP LogRecord (`event.name = "ostro.audit.head"`) and the gauge `ostro_audit_chain_seq`; a test advances the clock and observes one head per interval. The residual risk (a node-local attacker with disk write access can rewrite the journal since the last exported head) is documented by 14-24/14-25.
    - export: when telemetry is enabled, each committed record is offered to the Phase 8 OTLP logs pipeline as a LogRecord (`event.name = "ostro.audit"`, attributes = record fields except `details` flattened as `ostro.audit.detail.<k>`, severity INFO) through a bounded channel; a full channel drops the export copy (counted in `ostro_audit_export_dropped_total`), never the journal record.
    - node open, `ostro backup` and blob GC ignore `<data>/audit/` (a test creates the dir with content and runs open + backup + GC).
    - mutant `audit::mutant::skip_chain` (failpoints builds): writes a wrong `prev_hash`; a unit test proves verify catches it.
    - crash test (`audit_crash.rs`, `#[ignore]`, release, spawned failpoints binary or a child process writing through the writer): 50 iterations of commit-loop + `kill -9` at random times → after each restart every record acknowledged before the kill is present and verify passes.
  </behavior>
