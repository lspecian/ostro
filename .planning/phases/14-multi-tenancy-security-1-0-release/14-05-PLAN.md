  <behavior>
    API:
    ```rust
    pub enum Alg { MinisignEd = 1, MinisignEdPrehashed = 2, CosignP256 = 3 }
    pub struct TrustedKey { pub alg_family: KeyFamily /*Minisign|Cosign*/, pub key_id: Vec<u8>, pub public_key: Vec<u8>, pub comment: String }
    pub fn parse_trusted_key(text: &str) -> Result<TrustedKey, SigError>;          // "RW…" / .pub file / PEM SPKI P-256
    pub fn parse_signature(raw: &[u8]) -> Result<ParsedSig, SigError>;             // .minisig text | cosign base64 DER | bundle v0.3 JSON
    pub fn verify_module(bytes: &[u8], sigs: &[ParsedSig], keys: &[TrustedKey]) -> Result<Vec<ModuleSigEvidence>, SigError>; // ≥ 1 valid
    pub fn key_id_hex(k: &TrustedKey) -> String;                                   // minisign: 8-byte id LE hex; cosign: first 8 bytes of sha256(SPKI DER)
pub fn key_fingerprint(k: &TrustedKey) -> [u8; 32];                            // sha256(alg byte ‖ public_key bytes): stored in ext 113 (B1c)
pub fn reverify(bytes: &[u8], stored: &[ModuleSig], keys: &[TrustedKey]) -> Result<Vec<ModuleSigEvidence>, SigError>; // activation: match by fingerprint, re-verify each stored sig over the blob
    ```
    Cases:
    - minisign ED (prehashed) and Ed (legacy) signatures over a blob verify with the matching key; wrong key id → `UnknownKey`; tampered blob → `BadSignature`; tampered trusted comment → `BadSignature` (global signature).
    - Test signer for unit tests: an Ed25519 key from aws-lc-rs producing **legacy `Ed`** minisign-format signatures (sig = Ed25519(blob); global = Ed25519(sig ‖ trusted_comment)), so tests generate fresh signatures over arbitrary bytes; the prehashed `ED` path is covered by the committed rsign2 vector (BLAKE2b prehash is done inside minisign-verify).
    - cosign: generate a P-256 key with aws-lc-rs, sign the blob (ECDSA_P256_SHA256_ASN1_SIGNING), verify raw base64 DER and a bundle v0.3 JSON built by the test (`mediaType: application/vnd.dev.sigstore.bundle.v0.3+json`, `verificationMaterial.publicKey.hint`, `messageSignature.{messageDigest{algorithm: SHA2_256, digest}, signature}`); a `messageDigest` that does not match sha256(blob) → `DigestMismatch`; a bundle with a certificate/tlog but no `publicKey` (keyless) → `KeylessUnsupported`.
    - Fingerprints: two keys with the same 8-byte minisign key id but different public keys get different fingerprints; `reverify` against a key set lacking the signing key's fingerprint fails even if a key with the same key id is present; `reverify` over tampered bytes fails.
    - Multiple signatures: valid if at least one verifies against a trusted key; evidence lists every verified signature (alg, key id, sig bytes) and none of the failed ones.
    - Limits: signature input > 8 KiB, > 4 signatures, comment > 1 KiB → `TooLarge`; never panic on arbitrary bytes (proptest 512 cases over parse_signature/parse_trusted_key).
    - Interop: `fixtures/signing/blob.bin` (fixed 4 KiB bytes), `minisign.pub`, `blob.bin.minisig` (prehashed, made with `rsign sign -W` default mode) and `blob.bin.legacy.minisig` (`rsign sign -l` legacy if supported by 0.6.7; else generated by the test signer and labelled so in README) verify; README records the exact commands and that the secret key was discarded.
  </behavior>
