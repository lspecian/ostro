  <action>
Cargo.toml: package `s3-redb-bench`, edition 2024, publish = false, license Apache-2.0, empty `[workspace]`, deps `redb = "=4.6.0"`, `rand = "0.9"`, `clap = { version = "4", features = ["derive"] }`, `serde_json = "1"` (for machine-readable result lines); optional `fjall = { version = "=3.1.13", optional = true }` behind feature `fjall` (only compiled if Task 2 needs it). `[profile.release] debug = false`.

main.rs subcommands (clap):
- `bench --tier <t1|t2|t3|t2-2pc|t2-qr> --dir <path> --commands 200000 --warmup 20000 --batch 64 [--checkpoint-ms 100] [--checkpoint-batches 256] [--keys random|sequential]`:
  - Fresh db file per invocation (delete if exists). Tables: `runs: [u8;16] -> &[u8]` (~200 B value), `runs_by_status: [u8;17] -> ()` style index row, `outbox: u64 -> &[u8]` (~64 B), `meta: &str -> u64`.
  - Each command: insert 1 runs row (random 16-byte run id, or sequential when `--keys sequential`), insert 1 index row, insert 1 outbox/timer row, delete 1 previously inserted outbox row (keep a ring of prior keys). Each batch of B=64 commands is ONE write txn that also writes `meta["applied_offset"] = offset_after_batch`.
  - Tier semantics: t1 = every batch `Durability::Immediate`; t2 = every batch `Durability::None`, plus an Immediate commit when >= checkpoint-ms elapsed since last Immediate OR every checkpoint-batches batches (the Immediate txn writes `meta["checkpointed_offset"]`); t3 = every batch None and one Immediate at the end; t2-2pc = t2 with `set_two_phase_commit(true)`; t2-qr = t2 with `set_quick_repair(true)`.
  - Measure per-commit latency (separately for None commits and Immediate checkpoint commits), total wall time after warm-up. Output one JSON line: tier, commands, batches, cmds_per_s, batches_per_s, commit_p50/p99/max_us, checkpoint_p50/p99/max_us (t2 variants), checkpoints, db_file_bytes, equivalent_steps_per_s (= cmds_per_s / 3, assumption stated in a field), loadavg_before/after (from /proc/loadavg).
- `crash-child --dir <path>`: runs t2 indefinitely, printing `CKPT <offset>` to stdout (flushed) after every Immediate checkpoint commits.
- `crash-test --dir <path> --after-ms 3000`: spawns itself as `crash-child`, reads stdout lines, after `after-ms` sends SIGKILL (`child.kill()`), records the last `CKPT` seen (`last_ckpt`), reopens the db (time the open, including any repair redb performs), and reads `applied_offset` and `checkpointed_offset`. Assert: (a) the db opens without error; (b) `checkpointed_offset >= last_ckpt` and `applied_offset >= last_ckpt` (a checkpoint printed after an Immediate commit must be durable); (c) `applied_offset` is a multiple of the batch size (no torn batch). Do NOT assert on None-commits after the last checkpoint — they may or may not survive; report the gap `applied_offset - last_ckpt` instead. Print a JSON result line. Run it 5 times in a loop.

run.sh (bash, `set -euo pipefail`): takes an output dir for db files (default `${TMPDIR:-/tmp}/ostro-s3`, refuse paths under /mnt/), builds with `cargo +1.100.0 build --release`, captures `uname -a`, `df -T <dir>`, `lsblk`/`findmnt` info, `nproc`, `free -m` into `docs/spikes/data/S3/env.txt`, then runs each tier 3 times appending JSON lines to `docs/spikes/data/S3/results.jsonl`, then crash-test x5 into `docs/spikes/data/S3/crash.jsonl`. Accept `--quick` to run with `--commands 20000 --warmup 2000` and 1 repetition (smoke mode, writes to a separate `quick.jsonl` that is not committed).
