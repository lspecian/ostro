  <files>crates/ostro-bridge/src/http/mod.rs, crates/ostro-bridge/src/http/key.rs, crates/ostro-bridge/src/http/window.rs, crates/ostro-bridge/src/http/retry.rs, crates/ostro-bridge/src/http/target.rs</files>
  <behavior>
    - `derive_key(run_id, op)` = `"ostro-" + lower-hex(sha256(b"ostro/idem/v1" || run_id.as_bytes() || op.to_le_bytes())[..16])`, 38 chars. Pinned vectors (two run ids × two ops). An override is used verbatim. If the guest sets the configured header itself and the override field is absent, the guest's header value is the key and is not duplicated.
    - `window::decide(method, elapsed_nanos, target)`: idempotent methods {GET, HEAD, OPTIONS, PUT, DELETE} → Resend unless `force_window`; `resend == never` → Unknown; `elapsed + safety_margin < window` → Resend; otherwise Unknown. Table test with the boundary values. `Unknown` builds `NonRetryable{kind: effect_outcome_unknown, message: "in-flight effect older than idempotency window; not re-sent", details: {"op", "key", "elapsed_ms"}}`.
    - `retry::classify(err_or_status)` → `NeverLeft` (DNS failure, connect refused, TLS handshake failure: always retryable), `AfterSend` (timeout awaiting the response, reset mid-response: retryable only when a key header is sent and the window allows), `RetryStatus` (408, 425, 429, 5xx, and 409 whose body/headers indicate in-progress), or `Final`. The backoff follows `EffectRetry`. With no policy: up to 3 attempts for NeverLeft only (initial 200 ms, ×2, max 5 s). `Retry-After` (seconds) is honoured up to max_interval.
    - `HttpTarget::from_connection(Option<&Connection>, &EgressConfig)` parses the config, taking every default (timeout ← `default_timeout`, window ← `idempotency_window`, margin ← `safety_margin`, cap ← `max_response_bytes`) from `EgressConfig` (06-04, W1). An unknown `"v"` → error, surfaced as `NonRetryable{kind: connection_unknown}`.
  </behavior>
