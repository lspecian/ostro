  <files>crates/ostro-bridge/src/driver.rs, crates/ostro-bridge/src/registry.rs, crates/ostro-bridge/tests/driver.rs</files>
  <behavior>
    - `start` with a new key spawns a tokio task and records `(partition, run_id, op) → TaskEntry{cancel, started_at}`. With a running key it does nothing (attach) and increments `ostro_effect_attach_total`.
    - The task pipeline:
      1. `connector.target()`;
      2. `limiter.acquire`, where max_wait = min(cfg.rate_max_wait, effect timeout if HTTP `timeout_ms` is set);
      3. `gate.check` (Abandon → end without completion);
      4. `connector.execute(ctx, effect, gate)`, racing `ctx.cancel`. If `ctx.cancel` is cancelled when execute returns or is raced, end without completion. Connectors use this to signal a late Abandon from their own gate re-check;
      5. `encode_outcome`;
      6. `bridge_fail!("bridge::effect::before_complete_submit")`;
      7. `sink.complete`, retrying `Unavailable` with exponential backoff (100 ms → 5 s, until cancelled); `Dropped` is logged at debug.

      The entry is removed on completion.
    - A connector panic is caught (JoinHandle error): log `op`/`kind` and remove the entry, **without completing**. The next replaying activation re-drives (document this).
    - An unknown `EffectKind` (no connector registered) completes with `NonRetryable{kind: unsupported_op}`.
    - `cancel` and `cancel_run` trigger the tokens. `inflight()` reports the live entries. `shutdown(grace)` cancels everything after the grace period.
    - tests/driver.rs uses a `FakeConnector` (configurable delay/result/panic, counting executions), a `FakeGate` and a `FakeSink` (records completions, can fail N times with Unavailable). Cases:
      - double start → 1 execution, 1 completion;
      - Abandon → 0 executions, 0 completions;
      - sink Unavailable ×3 then Ok → 1 completion;
      - cancel mid-execution → 0 completions;
      - panic → 0 completions and the entry removed;
      - the encoded bytes equal `encode_result`;
      - 100 distinct ops → 100 completions, `inflight() == 0` at the end.
    - Metrics: `ostro_effects_inflight` (gauge), `ostro_effect_duration_seconds{kind}` (histogram), `ostro_effect_completed_total{kind,outcome}` with outcome = ok | the failure kind.
  </behavior>
