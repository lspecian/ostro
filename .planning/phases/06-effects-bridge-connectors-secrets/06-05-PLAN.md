      - an invalid name;
      - a name starting with `__ostro/`;

      - scopes `origin:<pattern>`… plus `body`;

      - a bare `*` origin is rejected.
    - `check_grant`: no grant → `NonRetryable{kind: secret_not_granted}`; origin not matched → secret_not_granted (the message names the secret and the origin, never a value); `in_body && !body` → secret_not_granted.
    - `SecretValue` Debug prints `SecretValue([REDACTED; n bytes])`. Values shorter than 8 bytes are rejected by `SecretValue::for_templating()` with `secret_not_granted` ("secret shorter than 8 bytes cannot be templated").

<task type="auto" tdd="true">
  <name>Task 2: Scrubber (scrub.rs) and sealed store (sealed.rs)</name>
  <files>crates/ostro-bridge/src/secrets/scrub.rs, crates/ostro-bridge/src/secrets/sealed.rs, crates/ostro-bridge/src/secrets/config.rs, crates/ostro-bridge/tests/secrets.rs</files>
  <behavior>
    - The scrubber builds patterns per value:
      - raw;
      - standard and URL-safe base64, with and without padding, at the 3 byte alignments. Use the stable middle of each encoding: drop the first/last partially-dependent characters, so a value embedded in a larger base64 blob is still caught;
      - lowercase and uppercase hex;
      - percent-encoding (every byte, and the RFC 3986 unreserved-preserving form);
      - JSON string escaping (`serde_json::to_string` minus the quotes, plus the `\uXXXX` forms for control characters).

      It uses aho-corasick LeftmostLongest and replaces each match with `[REDACTED]`. Tests take a 24-byte canary and embed each encoding at offsets 0, 1 and 2 inside 1 KiB of random JSON/base64 text; nothing survives. Empty value lists are a no-op. Overlapping secrets are both removed.
    - Sealed store:
      - `ciphertext = [1u8][nonce 12][ct+tag]`, `key_id = "aes256gcm:<kid>"` (kid = first 8 hex of sha256(key)), AAD = `b"ostro/secret/v1" || name || key_id`;
      - `open` fails on a wrong key, a flipped byte, a swapped name (AAD) or an unknown kid;
      - `plaintext-v0` returns the raw bytes (read-only; `seal` never produces it);
      - after `rotate`, new seals use the new kid and old ciphertexts still open.
    - `SealingKeyRing::load` order: `OSTRO_SEALING_KEY` (base64 of 32 bytes) → `sealing_key_file` → in `dev` only, `<data_dir>/sealing.key` (created with mode 0600 on unix, with a `tracing::warn!` that names the path and not the key). In server mode with no key → `Ok(None)` (the caller refuses to store secrets). Wrong lengths are an error.
    - `SecretsConfig` serde for `[secrets]` (providers order, sealing_key_file, env_prefix, file_dir, the vault and k8s sub-tables as `Option<serde_json::Value>`-like typed structs, which 06-13 interprets). Defaults per 06-DECISIONS.
  </behavior>

  </action>
