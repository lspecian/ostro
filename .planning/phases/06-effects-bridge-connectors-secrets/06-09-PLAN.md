<interfaces>
Read the existing `Ctx::http_fetch(&HttpRequest) -> Op<HttpResponse>` and the sql/object op handles from ctx.rs/ops.rs. The WIT records are `http-request{method,url,headers,body,timeout-ms,idempotency-key,retry,redact}`, `sql-request{connection,statement,params,exactly-once}` and `object-request{connection,op:string,key,body}`.

Object op strings (W7): `get | put | delete | head | presign-get | presign-put`. Output encodings:
- `get` → bytes;
- `put`/`head` → UTF-8 JSON;
- `delete` → empty;
- `presign-*` → UTF-8 URL.

Guest input/output conventions (the e2e plans rely on them; JSON via serde_json):
- fx-http: input `{"requests":[{"method","url","headers":[[k,v]],"body_b64"?,"idempotency_key"?,"semantic_key"?,"timeout_ms"?,"retry"?,"redact":[..]}], "parallel": bool}` → output `{"results":[{"status","headers":[[k,v]],"body_b64"} | {"error":{"kind","message"}}]}`. With `semantic_key`, the guest uses `ctx.idempotency_key(semantic_key)` as the override and also includes it in the JSON body as `"idempotency_key"`.
- fx-sql: input `{"connection","statement","params":[..sql-value JSON..],"exactly_once":bool,"repeat":n}` → output `{"results":[{"columns","rows","rows_affected"} | {"error":{..}}]}`.
- fx-object: input `{"connection","ops":[{"op","key","body_b64"?}]}` → output `{"results":[{"bytes_b64"} | {"error":{..}}]}`.
- fx-canary: input `{"echo_url","secret":"canary-name","header":"X-Api-Key","in_body":bool}` → sends a header (and optionally a body) with `{{secret:<name>}}` and returns `{"observed":{"status","headers","body_b64"}, "env":[...], "args":[...], "random":"<hex>"}`. env/args come from what the deterministic WASI shim exposes, so a test can assert the canary is absent from everything the guest can see.
- fx-ssrf: input `{"urls":[..]}` → one GET per URL, sequentially → output `{"results":[{"url","status"} | {"url","error":{"kind","message"}}]}`.
</interfaces>
