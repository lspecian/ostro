## Conventions (no format change)

- `SealedSecret{name: "<tenant|_>/<name>", ciphertext: [ver=1][nonce 12][ct+tag], key_id: "aes256gcm:<kid>" | "plaintext-v0"}`. AAD = `b"ostro/secret/v1" ‖ name ‖ key_id`. `kid` = the first 8 hex characters of sha256(key).
- `Grant{id: "secret:<module>:<secret>", subject: "module:<module>", scopes: ["origin:https://api.stripe.com", …, "body"?]}`.
- `Connection{name, kind: "sql-postgres" | "sql-mysql" | "object" | "http-target", config: JSON {"v":1, …}}`. For `http-target`, the name is the normalised origin (`https://api.stripe.com`); REST paths percent-encode it.
- `EgressPolicy{name: <module>, allow: ["https://api.stripe.com", "https://*.example.com:8443", "connection:orders-db", …]}`. A module without a policy has no egress.
- Reserved sealed names: `__ostro/token-key` (exists), `__ostro/presign/<connection>` (Phase 6). Guests and the admin API can never reference or set `__ostro/*`.
- Secret values shorter than 8 bytes are refused at `set` and at template resolution.

- `[secrets]`: `providers` (ordered, default `["sealed","env","file"]`), `sealing_key_file`, `env_prefix` (default `OSTRO_SECRET_`), `file_dir`, `[secrets.vault]` (`addr`, `mount`, `auth = token|approle|kubernetes`, `token_file`, `role_id`, `secret_id_file`, `k8s_role`, `cache_ttl` default `30s`), `[secrets.k8s]` (`namespace`, `kubeconfig`, `cache_ttl` default `30s`). The sealing key resolves from `OSTRO_SEALING_KEY` (base64), then `sealing_key_file`, then (dev profile only) an auto-generated `<data_dir>/sealing.key` (0600, with a warning). - `[egress]`: `allow_private` (default `[]`), `connect_timeout` (`5s`), `default_timeout` (`30s`), `max_response_bytes` (`4MiB`, hard max `64MiB`), `max_redirects` (`5`), `rate_max_wait` (`30s`), `idempotency_window` (`24h`), `safety_margin` (`5m`).
- `[connectors]`: `sql_max_rows` (`10000`), `sql_max_bytes` (`4MiB`), `sql_effects_retention` (`168h`), `object_max_get_bytes` (`16MiB`), `presign_default_expiry` (`15m`), `backend_ttl` (`5m`), `default_rate` (unset = unlimited), `public_base_url` (default: the API listen address; used in local presigned URLs).

## Standing rules (every Phase 6 plan carries them in `<phase_rules>`)

- Allocate ordinals and reserved names **only from `.planning/RESERVATIONS.md`, and only from Phase 6's block**. Phase 6 uses: Cmd 13; Intent 9 and 10; InvalidCode 15; rows in the existing keyspace #12 `effects`. It uses no journal kind, RejectReason, outbox kind, StartRun field, TerminalStatus or meta variant. If more is needed, STOP and report. Never borrow a Phase 7/8 block.
- WIT 0.1.0 is frozen: never edit runtime.wit, and Phase 6 adds no 0.1.N package. Cmd tags 1–12 are frozen. Existing prost messages, postcard structs and enums never gain fields or cases; new messages and appended variants are fine. Journal kinds are append-only, with no `EVENT_CODEC_VER` bump. Golden files are append-only. The golden_frozen prefix pins, the replay corpus and the format corpus v0.1 stay green and are never re-blessed.
- Only 06-01 edits the root `Cargo.toml`, `Cargo.lock`, `deny.toml` or any member crate's `[dependencies]`/`[dev-dependencies]`/`[features]`. The only exception is the separate SDK workspace (06-08: `sdks/rust`). A plan that finds a missing dependency STOPs and reports it.
- cargo-deny runs on the stock config. Never allowed: chrono, bincode, object_store, openssl-sys, native-tls, webpki-roots, mysql-rsa or the wasmtime `cache` feature. No duplicate tonic, tonic-prost, prost, prost-types, hyper, http, axum, opentelemetry or wasmtime. ostro-bridge never calls `reqwest::Client::new()` or `Client::builder()` outside `egress/client.rs`.
- A resolved secret value never reaches a log, a `Debug` impl, the journal, an error message or a test snapshot. Tests use canary values.
- The build stays warning-free and clippy runs with `-D warnings`. `bash scripts/ci-local.sh` is the gate. `FAILPOINT_CRATES` stays in sync with the ci.yml "Failpoint suites" step. Failpoints use the `fail` crate through `bridge_fail!`.
- Files shared with Phase 7/8 (`Cargo.toml`, `Cargo.lock`, `crates/ostro-objstore/**`, `scripts/ci-local.sh`, `.github/workflows/ci.yml`, `.planning/RESERVATIONS.md`, `.planning/STATE.md`): re-read the file from HEAD immediately before editing. Never revert or reformat another phase's lines.
- Never reference a Chronik clone path. No git remotes, no pushes. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Executors never run gsd-tools `state advance-plan`, `roadmap update-plan-progress`, `phase complete` or `requirements mark-complete`. Tracking files are edited by hand, and only where a plan says so.
- Verify commands that pipe output use `set -o pipefail`.
