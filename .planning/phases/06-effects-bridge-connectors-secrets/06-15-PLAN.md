**fx_http_e2e.rs** (in-process server, MockProvider, loopback allowed, module policy allows the mock origin):
- (a) A POST `/pay` via fx-http: the run completes, the request carried `Idempotency-Key` matching `^ostro-[0-9a-f]{32}$`, and `charges(key) == 1`.
- (b) An override key from the guest (`idempotency_key`) is used verbatim; `semantic_key` produces the SDK-derived key in both the header and the body.
- (c) Intent before I/O, with the failpoints feature: `bridge::http::before_send=return(wait:2000)`. While held, history shows EffectScheduled and the mock saw 0 requests.
- (d) A `/flaky?fail=2` GET with a retry policy completes 200 with the same key on all 3 attempts.
- (e) Ten parallel requests (`parallel=true`) all complete, each with a distinct key.

**fx_redrive.rs** (`#![cfg(feature="failpoints")]`, spawns `CARGO_BIN_EXE_ostro` with a data dir; configures through REST):
- **same_key_after_crash**: set `FAILPOINTS=bridge::effect::before_complete_submit=return(hang)`, start fx-http POST `/pay`, wait until `charges(key) == 1`, kill -9, restart without FAILPOINTS, and wait until the run is terminal. The run completes, `requests(key) == 2` (the re-drive), `charges(key) == 1`, and both requests carried the same key.
- **window_unknown**: http-target config `idempotency_window = "2s"`, `safety_margin = "0s"`. Hang as above, kill -9, sleep 3 s, restart. The run's effect completes with `effect_outcome_unknown` (the guest output carries the error kind) and `requests(key) == 1`.
- **idempotent_resend**: the same as window_unknown, but with a GET to `/status/200`. It is re-sent and completes 200; requests == 2.
- **suspended_inflight_wakes**: `/pay?delay_ms=6000` (longer than the 2 s hot wait, so the run suspends). Kill -9 once the mock has seen the request (before the response). Restart. The run completes via the LeaderAnnounced wake and re-drive; `charges == 1`.

Each test prints the timings and asserts terminal states within generous timeouts (60 s).
