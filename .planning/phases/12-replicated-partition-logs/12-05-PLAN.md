Scenarios (names are stable; 3 nodes, rf 3, min_insync 2, 4 partitions unless stated; each ends by stopping the cluster and running the disk + replica-identity + LA-rule oracles):
- placement: `placement_rf3_three_replicas` (every partition's meta `replicas` has 3 distinct members, `leader = replicas[0]` on a fresh cluster, leaders spread ±1 across nodes); `placement_rf1_single_node` (RF=1 node: replicas [1], ISR [1]) — **not pending** (RF=1).
- isr_honesty: `isr_empty_follower_not_in_isr` (blackhole Fetch from node 3 before any data; after writes, node 3 ∉ published ISR and `/admin` never lists it; `status::honest`); `isr_slow_follower_shrinks` (Delay Fetch on node 3 beyond `replica_lag_max` → removed by AlterIsr within lag + 2 s); `isr_lagging_follower_rejoins` (heal → re-added only after its durable LEO ≥ HW, measured on disk).
- hw: `hw_is_min_over_isr` (throttle node 3's fetch; HW reported by the leader ≤ node 3's on-disk durable end while 3 ∈ ISR); `hw_rf3_commits_within_rounds` (Pitfall 1: appends commit — acks arrive — within 5 s).
- stale_epoch: `fetch_with_stale_epoch_fenced` (after a failover, a fetch carrying the old epoch is answered FENCED; implemented by sending a raw `Fetch` over `InProcCluster::channel_as(follower, leader)` with the generated `ReplicationClient`); `fetch_with_future_epoch_unknown`.
- divergence: `leader_dies_with_unreplicated_writes` (cut the leader's outgoing Fetch responses, append k commands to it (no acks expected), kill it, failover, restart it → its divergent tail is truncated: replica identity below HW, none of the k commands in any committed log, all acked runs present); `isolated_leader_rejoin_truncates`; `two_quick_leader_changes_truncate` (KIP-279).
- failover: `failover_elects_isr_member` (kill leader; new leader ∈ previous published ISR within 10 s; runs resume and complete; `election::isr_only`); `whole_isr_dead_goes_offline` (shrink ISR to {1} by blackholing 2,3, kill 1 → partition offline (leader 0), **no** election of 2 or 3; restart 1 → back with no acked loss); `resigned_leader_moves`.
- min_insync: `writes_stop_below_min_insync` (min 2; isolate both followers → after shrink the leader rejects appends with Unavailable and **zero** acks are issued for commands appended before the shrink; HW frozen on disk); `writes_resume_when_follower_rejoins`.
