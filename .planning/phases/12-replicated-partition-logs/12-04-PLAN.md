pub struct ReplicaTracker { /* per replica: durable_leo, fetch_offset, last_caught_up_ms, last_fetch_ms, leader_durable_end_at_last_response */ }

Cases (input → expected), written as tests before code (`tests/replica_unit.rs`):
- tracker (B5): `on_fetch(r, fetch=100, durable=90, leader_durable_end_now=120)` → durable_leo(r)=90; a reported `durable_leo > fetch_offset` is capped at `fetch_offset` (INFO); `last_caught_up_ms` is set only when `fetch_offset ≥` the **leader_durable_end returned in the previous response** to that replica — the value the leader sampled **before** its read for that response (re-check W3; test: appends landing between the snapshot and the read do not move the target) (the value the follower could have had), never the leader LEO; durable_leo never decreases except via an explicit `on_truncate(r)` after a diverging response. **Continuous-append test:** the leader appends on every tick while a follower fetches every tick and always reaches the previous response's durable end → the follower stays caught up (lag ≈ one round) even though it never equals the moving LEO; a follower stuck one round behind that stops advancing loses caught-up after `replica_lag_max`.
- watermark: ISR {1,2,3}, durable {1:50, 2:40, 3:45}, min 2 → 40; prev 42 → 42 (monotone); published {1}, min 2 → prev (frozen); pending Add(4) with durable 30 → 30 is the min only if 4 ∈ maximal (yes); pending Remove(3) with 3 at 10 → 10 still counts; RF=1 {self} min 1 → self durable end; `append_allowed` false when |published| < min.
- isr: expand blocked when durable_leo < epoch start even if ≥ HW; expand allowed at ≥ max(HW, epoch_start) and caught up within lag; shrink when lag > replica_lag_max; never shrink the leader; at most one pending change at a time; after `AlterIsr` rejection the pending change is dropped and the published set is unchanged.
- divergence: `fetch_offset < log_start` → SnapshotRequired; **W5:** `fetch_offset == log_start` with `last_fetched_epoch ≤ epoch_at(log_start)` (the epoch in force at the leader's log start, from the history or the seeded cursor history) → Ok, so a freshly installed follower anchored at the snapshot offset never loops on SNAPSHOT_REQUIRED even when the leader's history below log_start was trimmed; `last_fetched_epoch = None` at `fetch_offset == log_start` → Ok; leader history [(1,0),(3,100)], follower last epoch 2 at 120 → Diverging{1, 100}; follower epoch 1 at 100 → Ok; follower epoch 1 at 110 → Diverging{1,100}; epoch older than oldest retained → SnapshotRequired; `follower_truncation_point(own=[(1,0),(2,100)], own_leo=150, 1, 100)` → 100, and iterating with a second diverging answer converges (KIP-279 case of two quick leader changes).
- failover (B1/W1): the elected ISR is always `isr' = isr ∩ live` (never adds a member) and the planner never returns an empty ISR; **ISR [1,2,3], leader 1 dead, live {2,3} → Elect{2, [2,3]}**; leader dead, ISR [2,3], replicas [1,2,3], live {2,3} → Elect{2, [2,3]}; ISR [1,3], replicas [1,2,3], leader 1 dead, live {2,3} → Elect{3, [3]} (2 is live but ∉ ISR: never chosen); preferred order respected; resigned node skipped; no live ISR member → Offline{keep: [last member]}; dead follower only → Shrink; live leader and full ISR → Nothing; never returns a leader ∉ isr.
- model (`tests/replica_model.rs`, proptest-state-machine, `PROPTEST_CASES` default 256): transitions Append, FollowerFetch(r), FollowerCrash(r) (loses non-durable tail), Fsync(r), ExpandProposed/Committed/Rejected, ShrinkProposed/Committed/Rejected, LeaderCrash + Elect(planner over live set), MinInsyncChange. Invariants: HW monotone per leader; HW ≤ every maximal-ISR member's durable LEO; **after any election, the new leader's log contains every offset below every HW ever published**; with |ISR| < min_insync no HW advance; no elected leader ∉ published ISR.
