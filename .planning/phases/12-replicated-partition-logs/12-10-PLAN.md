<task type="auto" tdd="true">
  <name>Task 2: Controller loop — bootstrap placement (any voter count), fresh terms, planner → ElectLeader/AlterIsr, resign handling, Member self-registration</name>
  <files>crates/ostro-cluster/src/{controller,bootstrap,members}.rs</files>
  <behavior>
    - `bootstrap::placement(voters_sorted, partitions, rf) -> Vec<Vec<u64>>`: partition p gets `[v[(p+i) % n] for i in 0..rf]`; deterministic; leaders spread ±1.
    - `Controller::run(meta, liveness, cfg, clock)`: active only while `meta.raft().status().is_leader`; on gaining leadership calls `liveness.on_became_controller()`. Each tick (100 ms default, clock-driven) over the meta assignment view:
      1. **Bootstrap placement (B2), any voter count:** epoch 0 means unplaced/Offline (never led, log empty). Once `ClusterInfo` exists, every partition with `epoch == 0` → `Put(Partition)` CAS `Some(0)` `{epoch 1, leader = replicas[0], replicas = placement(voters, p, rf), isr [leader], min_insync = min(cfg.min_insync, rf), isr_version 0, ext ElectionInfo{Bootstrap}}`. A single node gets `replicas = [self]` the same way. Partitions at epoch ≥ 1 with `replicas.len() == 1 < rf` are logged once as "not re-placed (Phase 13 `ostro cluster init`)". No fresh term and no failover action is taken for a partition while it is at epoch 0.
      2. **Fresh term on (re)start** — not part of the meta-leader loop: `controller::request_fresh_term(meta, self_id, p, min_epoch)` backs `AssignmentSource::request_term` and is called by the role lifecycle (12-13) when meta names this node leader at epoch e but **e ≤ the local log's latest epoch** (a restarted leader cannot reuse its epoch: apply's LA gate needs `la.epoch > cursor.epoch`). It is a **no-op at epoch 0** (placement first). It proposes, forwarded if needed, `ElectLeader{epoch = max(current + 1, min_epoch), leader = self, isr = current isr, expected_isr_version, info Startup}` where `min_epoch = local latest epoch + 1`; apply validates self ∈ ISR; `StaleVersion` → re-read and retry while still leader in meta; self ∉ ISR → do nothing and stay follower. A fresh single node therefore leads at epoch 1 straight from placement (log empty, 1 > none) and every later start takes a fresh term; a pre-Phase-12 single-node dir (epoch ≥ 1, replicas [n]) takes a fresh term on its first Phase 12 start. `AssignmentSource::resign` maps to `ResignLeader{p, epoch, self, info Resign}`.
      3. **Failover:** for every partition, `failover::plan(assignment, live, resigned)` → `Elect` → `ElectLeader{epoch+1, leader, isr, expected_isr_version, info Failover/Resign}`; `Shrink` → `AlterIsr{epoch, expected, isr}`; `Offline` → `ElectLeader{epoch+1, leader 0, isr keep, info Offline}` (only once per epoch).
      4. Proposal failures: `StaleVersion` → re-read and retry next tick; `Invalid` → log at error with the command (a planner bug or a mutant) and do not retry the same command; failpoint `elect::before_propose`.
    - `members::upsert_self(meta, me: Member)` runs on **every** node after meta is ready: read own record; CAS-put only if `addr/cluster_addr/repl_addr` differ.
  </behavior>
