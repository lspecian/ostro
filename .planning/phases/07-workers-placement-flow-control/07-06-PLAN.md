    - `ca_hash()` = `"sha256:" + hex(sha256(ca DER))`.
    - **Cluster-scoped CA (Phase 12 F13):** the CA belongs to the cluster, not the node: its CN and a stored `cluster_id` tie it to one cluster; `load_or_create` refuses a CA whose cluster_id differs from the node's; `ClusterCa::import_pem(dir, cluster_id, ca_crt_pem, ca_key_pem)` installs a CA shared from another node (the API Phase 12 uses to distribute it; Phase 7 exposes it but single-node behaviour is unchanged: first start still creates the CA locally).
    - `issue_node_cert(node_id: u64, sans: &[String]) -> CertifiedKeyPair` (1 y, serverAuth + clientAuth EKU; SANs = exactly one URI `ostro://<cluster_id>/node/<node_id>` + DNS names / IPs parsed from `[cluster] advertise` + `localhost` + `127.0.0.1` + `::1`), persisted as `node.{crt,key}`; reused while valid for > 30 days and SANs (incl. node id) unchanged, else re-issued. `NodeIdentity::from_der(cert_der) -> Result<NodeIdentity{cluster_id, node_id, not_after}>` via x509-parser. The worker and node URI schemes are disjoint: `WorkerIdentity::from_der` rejects node certs and `NodeIdentity::from_der` rejects worker certs (the cluster listener accepts only worker identities in Phase 7; Phase 12 accepts node identities for peer replication).
    - `sign_worker_csr(csr_der, token_id, worker_id, ttl) -> Result<Vec<u8> /*cert DER*/>`: verifies the CSR signature, ignores any subject/SAN requested by the CSR, sets SAN URI `ostro://<cluster_id>/worker/<token_id>/<worker_id>`, EKU clientAuth only, not a CA, `not_before = now - 60 s`, `not_after = now + ttl`. Rejects CSRs with non-ECDSA-P256/Ed25519 keys, or worker_id / token_id containing characters outside `[A-Za-z0-9._-]` (≤ 64 bytes).
    - `WorkerIdentity::from_der(cert_der) -> Result<WorkerIdentity{cluster_id, token_id, worker_id, not_after}>` via x509-parser; rejects certs without exactly one ostro:// URI SAN.
