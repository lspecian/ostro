    - `NodeFlow::admit(view, now)`: workflow paused or queue paused → `Paused`; queue concurrency (`concurrency`) reached → `QueueBlocked{until: None}`; key concurrency (`key_concurrency`, key = `concurrency_key`, empty key = unkeyed and never key-limited) reached → `KeyBlocked{until: None}`; if `view.first_activation`: queue throttle not ready → `QueueBlocked{until: Some(earliest)}`, key throttle not ready → `KeyBlocked{until: Some(earliest)}`; else `Yes(permit)` that increments the counters; dropping the permit decrements them and bumps `changed()`.
    - Counters: one `Mutex<BTreeMap<..>>` shared by every partition dispatcher on the node (D-W13: exact on a single node, per node in a cluster until Phase 13).
    - Throttle (W2, D-W24): a **hand-rolled GCRA** in `flow/limits.rs`, one theoretical-arrival-time per queue and per (queue, key), kept in **nanoseconds** (u64 ns on a monotonic base; `T = period_ns / limit`, `τ = T × (burst − 1)`), with `limit` and `burst` normalised to `max(1, value)` and `period_ms` validated > 0. Conforming iff `now ≥ TAT − τ`; otherwise `until = TAT − τ`. Throttle checks **both** the queue TAT and the key TAT first and advances neither unless both conform. Admission is **tentative**: `admit` advances the TATs (`TAT = max(TAT, now) + T`) and increments the concurrency counters inside the permit, remembering each previous TAT and the TAT value it wrote; `FlowPermit::commit()` (called by the dispatcher only after `Placement::reserve` returned Granted) makes it final; dropping an uncommitted permit rolls back: counters decrement, and each TAT is restored to the remembered previous value **if it still equals the value this permit wrote**, otherwise reduced by at most `T` but never below `max(previous, now)` (conservative). Time comes from `tokio::time::Instant`. No governor. Tests include a high-limit spec (5000/s, burst 1: 5000 admits over 1 s of paused time, spacing 200 µs without rounding to 0).
    - Keyed limiter/counter maps are bounded by `[flow] max_tracked_keys`, idle keys evicted after `idle_key_evict`.
    - `queue_weight(q)` = `QueuePolicy.weight.unwrap_or([flow] default_queue_weight).max(1)`.
    - `flow::install(ctx, cfg)`: `cfg.flow = Some(ctx.shared.flow.clone())`, `cfg.gauges = Some(ctx.shared.gauges.clone())`.
    - Metrics: `ostro_flow_admit_total{queue,result}`, `ostro_flow_throttled_total{queue}`.
    - Tests (`flow_control.rs`, in-process server harness read-only + direct NodeFlow tests): queue concurrency 2 with 10 runs → never > 2 leased at once (sampled from DispatcherStats/QueueGauges); key concurrency 1 across 3 keys → per-key ≤ 1 while different keys run in parallel; throttle 5/s burst 1 → first activations spaced ≥ ~200 ms, all runs eventually complete (throttle never rejects); a long run that evicts and re-activates is not throttled; pausing a queue via a meta CAS stops new grants and resuming continues them without polling; paused workflow likewise; weights 3:1 visible in grant order counts.
