- sdk-basic-v2: a separate component exporting (`sdk-basic`, version 2) whose output adds `"version": 2` — used by the activation/version tests (a component dispatches `run` by name only, so two versions of one name must live in two modules).
- sdk-retry: `#[workflow(name = "sdk-retry", version = 1)]`, input `{ "mode": String, "fail_times": u32 }`. Guest memory resets on eviction, so cross-activation attempt counts are NEVER derived from guest statics: the server tests count attempts from the journal (`StepAttemptFailed` events). Modes:
  - `"exhaust"`: step `flaky` with retry(max_attempts = 4, initial = "50ms", max = "200ms", backoff = 2.0, non_retryable = ["fatal"]) always returns `StepError::retryable("transient", ..)` -> expected journal: 3 x StepAttemptFailed + StepCompleted(Err); the workflow returns that error (run Failed).
  - `"recover_hot"`: same policy; the body fails while a `static ATTEMPTS: AtomicU32` (valid within one activation, i.e. the in-activation retry-now path) is < fail_times, then succeeds; output `{ "attempts": n }`.
  - `"non_retryable"`: body returns `StepError::non_retryable("fatal", ..)` -> exactly one attempt, StepCompleted(Err).
  - `"long_backoff"`: capture `t0 = ctx.now()` before the step; step `slow` with retry(max_attempts = 3, initial = "3s", max = "3s") fails while `ctx.now() - t0 < 2s` (live logical time advances past retry_at in the re-dispatched activation) -> one Requeue backoff (> hot_wait 2 s), then success.
  - `"exhaust_slow"`: retry(max_attempts = 3, initial = "3s") always failing -> used by the restart-between-attempts test (total attempts must equal 3 exactly).
  Every mode first runs a step `before` returning a static side-effect counter, and the output includes it, so tests can prove a completed step is replayed (one StepCompleted for `before` in the journal) rather than re-executed after restart.
- sdk-native: workflow that reads `std::time::SystemTime::now()`, iterates a `std::collections::HashMap` with 50 inserted keys, and draws `rand::random::<u64>()` (add `rand` from guests workspace pins, already `=0.9.5`) both outside steps and inside a step; output = JSON of all observed values. Replay must reproduce identical output.
