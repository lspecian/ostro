# {{name}}

An Ostro durable workflow module in Rust, generated by
`ostro init --lang rust`.

`src/lib.rs` defines one workflow, `hello`. It:

1. runs the durable step `greet`;
2. sleeps for three days (a durable timer that survives restarts and deploys);
3. waits for the signal `approve`;
4. returns `{"greeting": "hello <name>", "approved": <approve.ok>}`.

## Next steps

```sh
ostro dev --watch                                   # local server; rebuilds and redeploys on save
ostro deploy                                        # build target/ostro/{{name}}.wasm and deploy it
ostro run hello --input '{"name":"ada"}' --wait     # start a run and wait for its result
ostro signal <run-id> approve --payload '{"ok":true}'  # from another terminal
```

The run sleeps for three days before it waits for `approve`; `ostro dev --time-skipping`
skips idle time so you can watch it finish now.

## Toolchain

`ostro build` needs no preinstalled toolchain. With `[build] toolchain = "auto"` it uses
your rustup if it has the `wasm32-wasip2` target, and otherwise downloads a pinned,
sha256-verified Rust toolchain into the Ostro cache. Use `ostro build --docker` to build in
a container instead, and `ostro doctor` to see what is installed.

The SDK (`ostro-sdk`) and the test kit (`ostro-client`) are path dependencies under
`target/ostro/sdk/`, materialised by `ostro init` and `ostro build` from the SDK bundle
embedded in the `ostro` binary. `cargo clean` removes them; the next `ostro build` restores
them.

## Testing

```sh
ostro build          # materialises target/ostro/sdk if needed
cargo test           # spawns `ostro dev --ephemeral --time-skipping` (OSTRO_BIN or PATH)
```

`tests/workflow.rs` deploys this project to a throwaway server, starts `hello`, sends
`approve` and waits for the result. The server skips idle time, so the three-day sleep
takes seconds.
