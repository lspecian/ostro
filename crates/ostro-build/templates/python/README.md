# {{name}}

An Ostro durable workflow module in Python, generated by `ostro init --lang python`.

`app.py` defines one workflow, `hello`. It:

1. runs the durable step `greet`;
2. sleeps for three days (a durable timer that survives restarts and deploys);
3. waits for the signal `approve`;
4. returns `{"greeting": "hello <name>", "approved": <approve.ok>}`.

## Next steps

```sh
ostro dev --watch                                   # local server; rebuilds and redeploys on save
ostro deploy                                        # build target/ostro/{{name}}.wasm and deploy it
ostro run hello --input '{"name":"ada"}' --wait     # start a run and wait for its result
ostro signal <run-id> approve --payload '{"ok":true}'  # from another terminal
```

The run sleeps for three days before it waits for `approve`; `ostro dev --time-skipping`
skips idle time so you can watch it finish now.

## Toolchain

`ostro build` needs no preinstalled toolchain: it downloads pinned, sha256-verified copies
of uv, CPython and componentize-py into the Ostro cache on first use. Use
`ostro build --docker` to build in a container instead, and `ostro doctor` to see what is
installed.

The `ostro` SDK is pure Python with no dependencies. `ostro build` stages it from
`target/ostro/sdk/python/` (materialised from the SDK bundle embedded in the `ostro`
binary), so nothing is installed from PyPI. Workflow code runs inside a WebAssembly
component: keep I/O in steps and effects (`ctx.http`, `ctx.sql`, `ctx.object`).

## Testing

```sh
ostro build          # materialises target/ostro/sdk if needed
pytest               # spawns `ostro dev --ephemeral --time-skipping` (OSTRO_BIN or PATH)
```

`tests/test_workflow.py` uses the `ostro_env` and `ostro_project` fixtures of the Ostro
test kit (`ostro_client`, loaded by `tests/conftest.py`). The server skips idle time, so
the three-day sleep takes seconds.
